版本：1.6。状态核对：2026-10-28。起名、专业知识及外部 Skill 均为最终方案必需范围；实施顺序仍是公共底座 F01—F09 → 完整小说 N01—N12 → 漫剧 → 游戏。当前能力与真实来源/模型资格见 [实施状态](IMPLEMENTATION_STATUS.md)。

## 1. 已决定的产品体验

### 名字工作台：小说与游戏共用

入口在新建/批量创建/编辑角色旁，支持“一句话 + 可选高级条件 + 附件”。例如：给十位北方边城守军起名，朴素有辨识度，同族遵守辈分，不与已有角色近音。Agent 把要求整理成可修改的约束：题材、文化/语言、故事年代、风格、身份/阵营、姓氏、辈分、长度、发音、避讳和已有名字。性别只是可选约束，不强制套刻板模板。

每批默认20、最多100，支持分批补足。先检索已有名字素材和项目角色，再生成、去重、筛选。每条展示名字、读音/音译、风格标签、适合角色的理由、原创/采集/改造标识、出处与不确定性、重名/近音警示。支持锁定、收藏、编辑、筛选、整组比较、局部重生；锁定候选不被覆盖。不能用随机字拼接或固定名单冒充真实 Agent 高质量生成。

姓氏、个人名、字、号、昵称、称号分开；中文、日文、欧美、架空等都保留原文与音译。标签语言不等于文化来源。不会默认搬用知名小说角色名；无法完成全库检查时明确检查范围。中文简繁、同音和游戏显示名长度分别检查，不把“允许重名”与实体 ID 混为一谈。

作者确认后才创建角色或改名。同一名字允许作为素材复用，项目角色冲突按用户选择处理；事务检查角色预期版本，确保并发采用不会悄悄覆盖。改名不改变角色实体 ID，旧称保留为历史别名；进入既有附近章节和全书依赖分析，生成局部修文候选，复核后发布，禁止文本全局替换误伤其他人物或引用。

### 题材专业知识工作台

入口既在全书筹备，也在具体章卡/细纲/段落旁。例如：“南宋泉州商船靠岸有哪些手续，哪些动作最容易写错”。Agent 将请求拆成检索问题、优先来源、年代/地域、所需细节和采集上限。默认无需用户逐项确认检索计划即可研究；资料正式采用及内容发布仍由作者确认。

完整链路：问题拆解 → 检索公开来源 → 合规有限抓取 → 原件/哈希/时间/许可入库 → 解析与去重 → 原子事实卡 → 证据与冲突审查 → 用户编辑/确认 → 分区索引 → 章节 RAG → 专业细节审查。附件也走同一流程；支持取消、断点恢复、来源更新与撤回。

题材预设至少覆盖历史、刑侦悬疑、医疗、法律、军事、科技科幻、商战职场、生活职业。预设提供研究问题与来源选择方法，不把模型预先编造的“百科”当知识。事实卡保存结论、准确来源/定位、简短支持材料、适用年代/地域、证据状态（有支持/有争议/推断/未核实）、限制、写作应用、复核条件。

高质量不是检索数量：优先与情节因果有关的流程顺序、耗时、器物、术语、失败后果与感官细节；权威一手材料优先。转载链不算独立来源；资料之间的矛盾保留；现代制度不能直接套用古代。专业事实与写作建议分开，现实资料不自动成为虚构世界正史。未取得证据就列缺口，不生成虚假参考文献。

RAG 由章节问题、故事年代、地域、人物知情边界和预算共同约束，只检索有权访问的材料；已采用参考、研究候选、方法、正史分开输出。正文可自然融入知识，但上下文包保留来源定位供复核。Writer 与专业审查 Agent 独立上下文；来源更正使相关知识卡、上下文包、规划和章节进入待复核，生成补丁而非静默改文。

## 2. 数据与调度决定

| 对象 | 必需信息与状态 | 权威边界 |
|---|---|---|
| 名字素材与修订 | 原文、类型、读音、别名、标签、来源版本、许可、文化/年代及未知值、审核状态 | 共享素材可复用；不自动创建角色 |
| 起名请求/候选批次 | 提示词、结构化约束、已知名字快照、模型/Skill/索引版本、锁定项、费用、状态、采用映射 | 候选按项目隔离，角色采用服务负责事务 |
| 研究任务与来源版本 | 查询、原始链接、获取/出版/生效时间、哈希、解析器、许可、抓取结果、撤回状态 | 采集不等于可信，不执行网页指令 |
| 专业事实卡与修订 | 单个结论、出处定位、适用范围、证据等级、争议、写作用法、复核条件 | 编辑为新版本；证据存在性由程序核对 |
| 引用依赖 | 来源→事实卡→检索包→大纲/章卡/正文/游戏内容 | 变更传播及重新审查，不覆盖历史 |

公共阶段复用已实现的 MySQL 项目/资源修订、候选包、内容寻址存储、任务调度、费用门禁、混合 RAG 和依赖事件。命名筛选的结构化索引与专业事实卡投影在小说阶段按已确定字段落库；它们是可重建索引，不另建脱离来源链的“真相库”。如需增表，必须纳入迁移、备份恢复、清理保护和来源授权覆盖，再启用迁移。数据库结构变化依照正式迁移与恢复流程管理，不能绕过版本和来源登记。

预设角色：起名策划、名字质量审查、题材研究、专业证据审查；复用公共 Researcher/Critic 的模型绑定和预算控制，各有独立任务与上下文。工具限定为检索/读取批准资料/产生候选，不能自行授权联网、付费、执行脚本或发布。所有必要方法随系统提供，允许改写为本地派生。最终质量要通过相应题材、模型与任务的保留集评测，不用 schema 通过代替文学效果。

来源目录实现契约：免费采集入口支持`wikipedia`（术语线索）、`europe_pmc`（英语开放论文）、`wikidata_names`（姓名条目）和`official_reference`（批准官方链接）。研究执行稿固定来源，语言、页面身份、回执与来源相互校验；旧版省略来源时保持百科行为。Europe PMC原始XML与SHA256、作者、出版信息、DOI和逐篇许可分开保存，仅明确CC-BY/CC0的原文进入复用库；开放获取标记不等于许可。Wikidata采集原始JSON、实体修订、名字分类与指定语言标签，CC0数据不自动取得文化、年代、读音或流行度结论。每个公开请求有固定主机、体积、时间和全局并发限制；503/429及maxlag触发对应来源退避，不用一个来源的冷却拖住其他来源。

官方链接仅允许代码目录中的精确主机和公开正文路径（中国政府网、全国人大、最高法院、国家统计局、NIST、美国国家档案馆、国会图书馆），拒绝凭据、查询参数、跳转与私网；每个采集步骤先robots、后正文，最多两个请求且合计35秒，沿用现有一分钟租约和45秒活动超时。没有明确全文复用许可时，下载对象是`official-reference-receipt-v1` JSON：来源题名/链接、网页字节SHA256、采集时间和最多160字摘录，`capture_extent=metadata_excerpt`；不是HTML原件，也不构成全文许可。导入报告保留待核对项，采用须明确接受部分材料。网页日期不是法规生效日期，官方载体不自动证明每条内容的结论或权利。`reference_url`与不超过JS安全整数范围的兼容数字键共同校验，规范URL及网页指纹是实际身份；旧来源不接受这个附加字段。

名字入库沿用私人素材库：从已采集原件预览，编辑后明确保存；同实体/语言不覆盖已有人工作品。每项`source_import_id`校验当前作者、作品分支和原件类型；保存后的资料库保留引用的原件及来源报告，不依赖打开通用导入编辑器。新增字段在旧稿为空时省略，不改变旧输入指纹。所有条目仍是可编辑参考，直接起名的Agent使用冻结素材库版本；采集并不直接新增或改名角色。实现、公网来源与真实质量状态见 [实施状态](IMPLEMENTATION_STATUS.md)。

批量整理入口复用后台研究采集的姓名原件：`GET /novels/:book/character-designs/name-catalog/sources?after=<id>`每页50项并返回后续游标；`POST .../name-catalog/sources-preview`一次最多100个不重复原件ID，预览不写库，沿用原保存与版本冲突门。这个批次上限不扩大生成上下文的必需输入上限；素材库600条/240KiB上限仍在，容量不足时整批报错，不截断或部分保存。

免费来源与本地存储优先；不采购姓名库、搜索 API 或学术全文。无付费授权时只使用免费采集和现有离线能力，真实收费模型调用保持阻断并说明用途与上限。公网采集遵守来源条款/robots/限流，防止内网访问与重定向绕过；版权受限材料保存许可允许的摘要、短引用和定位，不默认复制全文或整部小说角色表。

接口与许可依据：[Europe PMC REST](https://europepmc.org/RestfulWebService)、[开放论文逐篇许可](https://europepmc.org/downloads/openaccess)、[Wikidata数据与CC0](https://www.wikidata.org/wiki/Wikidata:Data_access)、[Wikibase API](https://www.mediawiki.org/wiki/Wikibase/API)。来源机构提供的接口与许可不代替专业结论审查。
