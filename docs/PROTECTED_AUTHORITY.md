# F08 受保护撤销账本与 T0 删除

文档核对：2026-10-28。本文定义专项契约与验证边界；当前工程实现、安装和资格状态见 [实施状态](IMPLEMENTATION_STATUS.md)。

本页定义 T0 访问撤销和隔离恢复时的当前撤销重放，T0 本身不执行后续物理删除。完整生命周期仍包括 7 天受限回收、30 天在线清理、最坏 65 天备份淘汰及至少一年账本保留；受限回收、物理清理、自动保留期执行和恢复为新项目由现行 F08 流程承接，其工程实现与资格见 [实施状态](IMPLEMENTATION_STATUS.md)。本页的早期 T0 专项结果不能用作当前整体进度，也不能证明独立介质灾难恢复合格。

## 权威存储与事务

- `studio_authority` 是同一台本地 MySQL 上的独立 InnoDB schema，不在应用业务 schema、项目归档或恢复目标内。
- `sources` 保存源服务器 UUID、原业务数据库名、随机账本 ID、协议版本和可信初始基线的提交时间。应用账号只能 SELECT。
- `events` 仅追加项目创建、项目删除、Skill 撤销、能力版本撤销。应用账号只能 SELECT、INSERT，没有 UPDATE、DELETE 或 DDL 权限。
- 每个事件由账本 ID、事件类型、项目 ID、资源 ID 唯一标识；重复写入不改写原始证据。来源由业务事务内的 `@@server_uuid` 与 `DATABASE()` 确定，客户端不能选择。
- 创建项目、撤销 Skill/能力、删除项目均通过**同一个 `sql.Tx`**写业务表和跨 schema 账本。事务失败则一起回滚；没有异步 outbox 的时间缺口。

受信本地初始化在 API/Worker 停止时运行，持有与业务迁移相同的 `<business database>:schema` MySQL advisory lock。DDL 可重跑；首次完整项目和撤销基线与来源标记同事务提交。重复初始化验证既有来源而不清空或替换账本。服务启动和相关业务操作要求有效账本；不可用时拒绝操作，不退回业务库作为撤销权威。

官方依据：[MySQL 8.4 事务提交与回滚](https://dev.mysql.com/doc/refman/8.4/en/commit.html)、[跨 schema 表名限定](https://dev.mysql.com/doc/refman/8.4/en/identifier-qualifiers.html)、[MySQL GRANT 的表级权限](https://dev.mysql.com/doc/refman/8.0/en/grant.html)。事务仅使用 InnoDB，并通过真实跨 schema 回滚和进程终止测试验证；不依赖混合存储引擎的原子性。

## T0 项目删除

项目所有者必须提交完整项目名称、预期 revision 和 operation ID。成功后写入 `projects.deleted_at`、提升 revision、追加受保护删除事件，并保存操作回执与审计。

中央 `projectTx` 同时校验业务删除标记和受保护项目事件。列表、读取、检索、任务创建、Worker 执行以及私有文件的服务入口均受此检查约束。已运行的外部调用不会被描述为已经取消，但后续权限检查和结果提交不能越过删除门禁。旧业务行恢复成 `deleted_at=NULL` 也不能重新授权。删除响应丢失后的重试必须同时对账业务回执和受保护删除事件。

UI 明确提示访问立即撤销、历史与文件仍保留、该 T0 操作不执行物理清理，并要求输入完整名称。T0 不删除历史、原文对象或备份。

Skill 与能力使用时仍遍历不可变血缘；遍历后针对完整祖先 ID 集合查询一次受保护撤销记录。旧业务库丢失撤销行不能复活撤销祖先。

## 备份与恢复

新备份格式仍为 format 1；schema 25 起 manifest 增加账本 ID 与协议版本，schema 26 另加入私人生成预览。快照在同一一致读事务中读取来源和账本标记。恢复核对原服务器 UUID、原数据库名和账本标记，复制前后分别读取当前完整权威状态；快照包含已删除项目时拒绝恢复。

恢复只读取独立受保护 schema，不需要原业务数据库存在。CLI 可使用独立 `STUDIO_AUTHORITY_DSN`；未单独提供时仅沿用来源连接参数并清空原业务数据库名。恢复目标仍必须是新建 `studio_restore_<32hex>`；用户禁用、权限/绑定不重开、任务不运行、费用待核对。

schema 24/25 备份继续受支持：先验证原始字节及对应迁移校验和；schema 24 固定旧项目列布局追加空 `deleted_at`，24/25 均固定补空预览表，由可信本地迁移创建当前目标。没有账本标记的旧包仍须匹配可信账本中的精确原来源和最新项目/撤销状态；不接受包内 JSON 的“完整”声明作为权威。

## 已验证与边界

真实临时数据库测试涵盖跨 schema 回滚、事务子进程提交前被终止、重连后持久化、重复事件、来源错误、权限拒绝、祖先撤销、T0 读取/检索/任务/私有对象阻断、操作回执重放、快照后撤销重放、删除项目拒绝及 schema 24 升级恢复。恢复测试实际移除了本测试创建的原业务 schema，并验证独立账本与 CLI 恢复；没有删除真实项目。

这是**独立于业务数据库丢失**的恢复权威，不是独立物理故障域。同一 MySQL 实例或整个磁盘损失仍可能同时丢失业务和账本；尚无外部受保护介质时，不宣称整机灾难恢复能力。上述事务子进程用例只终止独立测试事务进程，不构成 MySQL 服务崩溃或整机灾难恢复演练。
