# 统一创作记忆系统：研究与架构决定 v1.7

维护日期：2026-10-28。适用于小说、漫剧、游戏，属于公共底座。本文区分领域契约、已有实现和验收目标；功能状态见[实施状态](IMPLEMENTATION_STATUS.md)，研究机制不构成本项目性能实测。

## 一、结论和选型

采用 **Go 编排的分层记忆与上下文编译器 + MySQL 权威持久化 + 版本化图关系/混合 RAG + 有界本机缓存/Valkey 可替换缓存**。Python只承担本地嵌入、重排及文图解析；Vue提供作者可理解的记忆、引用和一致性操作。沿用Temporal、IP修订、候选采用、联合发布、依赖传播、备份恢复，不平行建设另一套“真相数据库”。

选型采用分层领域契约与既有系统组合，以满足单人、本机、多媒介和严格版本需求。直接接入通用记忆框架仍需实现权限、正史、改编、回退、成本和媒体授权适配。首期不增加必需Neo4j/Qdrant服务，也不让模型自动修改权威事实；保留适配接口，容量基准证明必要时再评估独立检索引擎。嵌入、MySQL、缓存协议和调度继续复用相应开源实现。

比较的三条路径：全文输入长窗口减少检索组件，但输入成本、覆盖和泄漏仍需控制；通用记忆服务需要领域与权限适配；分层编译与已有权威数据结合需要实现领域契约，可避免重复存储和调度。本项目采用第三条路径。版本按[社区兼容基线](COMMUNITY_STACK_BASELINE.md)，工具链升级与记忆数据迁移分别验证。

## 三、五层记忆和四种权威

| 层级 | 内容 | 生命周期/查询 |
|---|---|---|
| L0 原始档案 | 原文、附件、已采用正文、图片/声音、工具回执 | 不可变内容哈希；所有摘要可回指原始定位 |
| L1 叙事核心 | 主题命题与边界、主线因果骨架、人物核心、世界硬规则、必须保留高光 | 有版本的作者确认契约，按任务必须覆盖，不能仅依赖向量top-k |
| L2 长期结构与阶段状态 | 人物关系/认知、事件/因果、角色弧、伏笔承诺与兑现、物品/伤势/服装、设定、职业知识 | MySQL修订/时间关系/来源；按分支和场景投影，历史不覆盖 |
| L3 中期叙事摘要 | 场景→章→卷→全书的情节、角色、因果摘要与未闭环清单 | 每条有source revision/range和coverage；原件变更则失效，不能只反复摘要旧摘要 |
| L4 短期工作记忆 | 本任务目标、章/场景卡、近段原文、待解决问题、当前用户反馈、锁定候选与执行进度 | MySQL checkpoint跨重启；只对指定作者/任务可见，缓存仅加速，不因缓存过期丢草稿 |

四种权威不得混淆：①作者已确认的创作意图/未来计划，②已发布故事事实，③外部专业参考，④尚未采用的候选/个人草稿。真实发生、计划发生、人物相信、对外宣称、模型推断分别保存。某个故事主题不是现实真理；写作计划不是剧情已发生；学习到的Skill不是工具权限。

## 四、保证“不变味”的领域对象

NarrativeContract 保存主题问题、价值张力、叙述立场边界、主线目标、主要因果里程碑、类型/语气、角色承诺和禁止意外改写项。每个条目有稳定ID、作者确认版本、作用范围和重要程度。不是把中心思想变成每章重复说教；检查的是人物选择及后果是否仍支撑作品意图。

Highlight 保存角色归属、铺垫条件、核心选择/行动、代价、转折、情绪回报和不能丢的意义；状态 planned→seeded→earned→paid_off（撤回单独记录）。跨媒介允许压缩/合并/视觉化，但必须建立来源高光→目标场景/镜头/任务的覆盖映射，给出保留/转化/合并/省略、理由与证据。必保项省略或语义大改必须形成作者决策，不能由摘要悄悄消失。ID覆盖只能证明有对应项，语义保真仍需独立评审。

角色状态拆为身份核心、阶段外貌/装备/伤势、知识与信念、关系和目标；同一entity_id关联文本和已获批媒体资产。不要把后期“独眼”外貌带回前期。游戏以可信事件更新角色认知，存档回退必须回到对应世界状态与记忆分支。

## 五、时间与隔离契约

共同范围键：workspace/project/branch + canon revision + actor/permission epoch + purpose + perspective + story position + timeline/save（游戏） + task session（短期）。时间明确区分：故事发生区间、知情/向读者揭示时间、系统记录/发布版本。叙事顺序不等于事件发生顺序，倒叙必须分别传入。

先校验权限、正史分支、可见性、时间与来源有效性，再做检索排序。作者可以读取未来计划供编剧控制，NPC只得知其当前存档中已知信息；Writer得到“可表达材料”与“隐藏创作约束”两个独立槽。Critic可读更广资料，但报告仍按权限过滤。摘要继承来源中最严格可见性，不允许从私有/未来内容压成公共摘要。跨分支引用仅作带出处参考，不把另一支的结局当当前发生。

2026-10-27小说叙事补充：Writer允许不绑定人物身份，以支持新书首次写作、全知或多场景叙事。空视角只取得当时公开的事实/证据；特定人物才知道的信息不因此公开，作者隐藏约束仍单独传递，场景揭示按已确认细纲控制。指定了人物却找不到身份时仍拒绝，NPC始终要求有效人物身份。记忆中的作者控制项保持control通道，空视角不读取restricted证据。选择器与记忆编译定向反例已通过；不以此宣称模型一定不会泄漏，仍需独立Critic审查。

小说动态账本与静态设定的边界：Bookkeeper从实际私人章稿提取带逐字引文的剧情候选，不读取Writer的未来plans或自评。事件、信念、传闻、意图、回忆、梦境分别保留类型与语境；原文定位只证明出处，不代替语义审查。普通剧情更新采用章节账本资源及记忆版本，不自动推进IP设定head，因而不会每章使全书规划失效。确实改变世界规则/人物长期设定的内容另提IP修订并走影响分析。正式发布将章节控制、正文和账本固定为同一release，并在提交事务中生成对应记忆投影；私人草稿不能伪造该发布证明。此工程路径不证明真实模型记账或文学质量合格。

## 六、上下文编译与效率

1. 从任务/场景卡得到目标、视角、时间、涉及人物、主线里程碑、高光/伏笔ID、输出预算与模型能力。
2. 固定所有版本，构造请求快照；读取当前权限与撤销状态。可复用缓存仅在这些键匹配后使用，缓存不提供授权证明。
3. 首先加载本任务必需叙事核心和已锁定原文，再做实体别名/结构化SQL、关系/因果有限跳转、MySQL关键词、BGE语义检索；按目的选择局部场景或全书专题路线。
4. 归一去重并融合排名；优先依赖前置事件、到期未兑现承诺、关键对比/反转与最新有效状态。必要时一次查询扩展/重排，避免不受限Agent反复搜索。
5. 核心约束和依赖闭包必须完整；只对可选候选做预算筛选。预留system、工具schema、实际输出和安全裕量。各模型用相应tokenizer或明确保守估算，不能把中文字符数当精确token数。必需项放不下就拆任务/采用经确认短版本或报容量缺口，不截断半条事实。
6. 输出 MemoryManifest：版本、来源段落/资产、纳入理由、预算、缺口、被排除原因（不得泄露不可见条目细节）、检索/嵌入模型版本、覆盖结果和失效条件。持久保存以支持重现。
7. 生成只是候选；Bookkeeper从真实正文独立提出事件/角色/摘要增量，Critic核对事实、主题、高光与伏笔。用户采用/正式发布后事务提交权威状态和outbox；更新派生索引与摘要走后台，依赖未就绪则阻止受影响生成，不全书阻塞。

默认写作上下文预算按模型可用窗口比例分配，初值建议核心10%、当前任务/近文35%、人物/事件20%、长程承诺15%、专业资料10%、余量10%；这是可调策略，不是强行挤满。小窗口拒绝超量必要输入。卷审走按主题/角色分批再聚合；按引用精确定位原文，不让多层摘要替代证据。

本机目标而非已测承诺：30万字检索包热命中P95≤200ms、未命中≤2s（不含收费模型与首次嵌入）；峰值内存有硬上限；与全历史基线相比输入token减少≥50%且必保锚点漏召回为0、语义质量不得下降。未达标先定位SQL扫描/向量解码/过大关系闭包，再启用索引优化或可替换ANN；不能靠隐藏遗漏满足延迟。

## 七、MySQL、缓存与持久化

权威正文/资源继续使用现有资源修订+BlobStore，不复制成另一份聊天事实库。schema35已采用三张专用表memory_items、memory_revisions、memory_sessions；证据锚点随不可变修订保存，manifest复用context_packages，调度复用既有任务及outbox，不为每层重复建表。条目与session创建/修改均使用operation_id和expected_revision；session收据已接现有operations及归属登记，同请求重放返回当前已授权记录而不覆盖后续编辑。Vue独立暂存未确认输入和冻结请求，刷新可恢复，未知保存结果先按原请求核对，跨窗口不共写一份稿。未来长篇查询确有需要时再为来源边/投影新增规范化索引，不提前建立第二事实库。

MySQL保存短期checkpoint、长期修订、有效区间、来源、采用、撤销和依赖；对象存储保存大正文/图片/声音。内容发布事务同时写outbox，后台索引通过唯一(source revision, extractor, embedding, policy)去重。模型调用不在事务中；服务重启按checkpoint恢复，不重复未知收费请求。

缓存接口可替换，已实现本机有界LRU作为默认层；Valkey是多进程共享缓存的设计选项，适配器及singleflight尚未启用。当前键包含内容/来源清单哈希、编译器/检索版本及上述权限时间范围，TTL、条数/字节上限、拷贝隔离和并发保护可用。缓存保存派生结果，不独占草稿/费用/任务状态。未来Valkey的AOF/RDB只改善热启动，不成为权威或备份替代；丢失、不可用、淘汰均回源MySQL。当前Windows安装不依赖Valkey或Linux；引入共享缓存须另验部署与失效语义，不能由设计选项推断Linux/Docker可运行。

过期/撤销/修改→outbox→依赖闭包标stale→缓存换代/删除→按源重建。所有读取重新核对当前权限和版本，不能靠异步删除cache保证隔离。项目删除与恢复：撤销优先、缓存清空、恢复新namespace，索引可重建；备份必须覆盖checkpoint和权威记忆，绝不恢复过期权限或未来存档记忆。

现有备份/日志/来源保护强约束继续保留。每次新增记忆表必须在同一变更中补齐schema指纹、列分类、外键顺序、备份导入导出、变更日志重放、保留来源及删除范围，然后才启用迁移；以一次定向契约测试+里程碑恢复测试覆盖，避免每个字段都反复全套。

## 八、跨模块全流程

小说立项→主题/主线/人物核心确认→大纲/暂定章节→细纲→每章记忆编译→正文候选→独立记账/审查→采用发布→摘要/关系/伏笔增量→卷审/修订→成书。手写、附件、专业研究和角色起名同样进入来源链；无Key可手写、编辑和导出，不能用固定示例伪造生成。

漫剧改编先生成保真契约和覆盖表，再从小说源版本编译集/场景/镜头上下文；角色参考图、阶段服装、声音、场景物理状态独立版本。图像一致性需生成后实际审查，不宣称“记忆库已解决脸一致”。游戏构建时编译世界/任务/角色规则与记忆种子，运行时隔离NPC、玩家存档和权威事件，模型不控制数值结算。

任何模块修改核心主题、人物、来源高光、专业事实或资产，先显示影响范围和缺口，再产生局部补丁与审查；冻结产物保留旧兼容清单，不假装与新版本一致。公共记忆契约归属底座；漫剧与游戏专业UI及产物按对应阶段实现，不能由共享领域对象推断专业模块已经可用。

## 九、验收与验证简化

资料提炼桥接已实现：作者选已发布资源，服务端装配严格协议；Recipe在执行校验链重验来源，结果原子导入memory_items/revisions私人候选并复用采用机制。无新增表、无模型自动晋升；单批有界输入拒绝超限。场景/章/卷/全书分层整理、精确引用、增量待办和保留原身份的逐层重整已有实现，章节发布也已接入记忆投影；具体工程状态见[实施状态](IMPLEMENTATION_STATUS.md)，这些机制不能代替全书长记忆和真实文学验收。

结构化上下文选择在精确IP版本内先作知情/时间判断，保留锁定实体/命题、显式必需项、世界规则和身份/关系/知情人/能力前提闭包；其余按人物、别名、任务相关性和当前状态进入有界候选。NPC仅从已知事实选择且不暴露隐藏集合数量。可选背景与必要记忆或完整引用争用容量时，退回硬约束重编译并明确报告遗漏；硬约束仍超限则拒绝生成，不截断。MySQL context_packages冻结结果，Vue显示覆盖范围；选择器与数据库反例验证不证明模型一定不会泄漏，仍需独立审查。

平时：编译/类型、改动行为的定向测试，单个缺陷只保留一次真实反例；低风险样式/文案不做昂贵矩阵。核心门禁（越权、跨分支、未来泄漏、并发采用、预算、不可变内容、恢复）不可跳过。里程碑集中进行数据库/浏览器/恢复/长篇压力与真实模型质量验收，固定证据复用，除非相关代码/依赖/数据改变，不重复同一检查。

记忆专项覆盖别名、远端伏笔、前章回改、同名人物、矛盾来源、复杂关系、未来状态、倒叙、公开摘要泄密、缓存污染、缓存全失、进程中断、出错合并、改编高光遗漏和存档回退。确定性规则的验收要求为适用用例全部通过；语义理解须独立样本与实评。30万字规模可先以明确标识夹具测性能和状态，真实文学验收仍需明确启用的模型及原质量标准，不相互替代。
