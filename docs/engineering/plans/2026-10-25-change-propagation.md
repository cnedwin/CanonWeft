## 结果与实现顺序

用户发布设定或资料后，相关作品收到可恢复的复核状态；影响分析包含已登记引用、语义疑似与未检查范围。用户可选择继续使用、复核或局部修订，看到实际前后差异，明确采用后一致发布。修订失败时旧正文仍可读。回退产生基于当前版本的新补偿候选，保留后来改动。

1. **发布事件实际传播**：复用不可变 `change_plans` 保存业务完成回执和目标版本影响记录，回执 ID 由事件 ID 确定；原 outbox 的处理时间只表示持久调度已接受。`ip.published` / `release.published` 走 Temporal 工作流；Worker 重投不重复登记。读取事件引用的实际已发布版本与前置版本，不信任 outbox 中的自由正文。保存确定性来源变化和完整目标水位，冻结节点继续传播。删除项目停用任务且不恢复访问。此步骤不增加表或迁移版本，后续执行/决定状态再按实际契约引入。
2. **覆盖、决定与执行**：在不可变 ChangePlan 外保存执行状态和版本化决定。区分确定影响、语义疑似、尚未检查与已证据化仍适用；不把闭包外对象标为安全。分页覆盖固定目标版本全集；每批冻结上下文、能力与索引。使用现有生成、资格、费用和独立审查服务，模型只建议边和动作。过期计划须重新计算。
3. **最小补丁与依赖组**：以稳定资源 ID、版本、Unicode 范围、原片段 hash 定位；程序验证非重叠锚点并应用到完整正文。实际改后文本分别交给 Bookkeeper/Critic；写作者不能自报通过。用户可编辑候选，修改会使旧审查失效。组内必要成员全部采用才可交给既有 Release 事务发布。自动最多两轮，人工继续修改不限。
4. **补偿版本**：从旧发布计算被选择变更的反向差异，与当前版本三方合并。冲突需显式处理；不直接倒退发布头，不覆盖无关后来工作。继续走同一影响、审查、采用与发布路径。
5. **总体验证**：真实数据库/Temporal/本地对象/索引；浏览器从发布、看影响、生成与修改补丁、重审、采用至发布及回退。模型传输夹具只能证明编排和门禁；文学/漏检质量单独保留真实模型验收项。

## 实施约束

传播是确定性维护，不借用已撤权作者的身份执行写作；内部消费者只可写影响记录。人工决定、生成请求、候选采用和发布均重新检查当前登录者、项目与分支权限。

每条影响记录绑定事件、源前后版本与目标确切版本。晚到旧事件不能替换较新的用户修改或把已过期任务标为完成；重复投递只返回已有回执。真正已知无影响须有完整覆盖和绑定证据，不能靠未发现引用推断。

同一分支内沿现有联合发布事务处理设定/正文/账本/索引。跨分支保留各自明确的兼容发布集合；需要跨分支原子修改时必须在同一库事务内协调全部头，不能多次提交后称原子。

正文、原文、理由与方法文本不进入永久状态回执。业务内容使用版本化对象；回执只保存必要 ID/hash/闭合状态/费用元数据。新数据必须声明期限和项目归属。当前账单 UNKNOWN 不释放占用，不重新发送已发请求。

## 每步回归

| 步骤 | 必须复现并通过的行为 |
|---|---|
| 传播 | 重投一次生效；数据库提交后丢回执恢复；Worker 重启；冻结仍传播；当前已删除项目拒绝；旧事件不覆盖新头；闭包外 hash 不变 |
| 覆盖/执行 | 缺索引/缺页/截断保持 PARTIAL；同名身份与跨分支隔离；远端未登记引用进入候选；过期图/当前撤权阻断；取消和 UNKNOWN 不重发；无收费授权零请求 |
| 补丁 | 过期 hash/锚点偏移/重叠/越界拒绝；真实改后全文用于独立抽取复核；半个依赖组不能发布；迟到结果不替换正在编辑文本；重复采用幂等 |
| 补偿 | 只恢复选择范围；保留后来无关编辑；同字段冲突阻断；原发布仍可读；回退后可继续创作；权限撤销阻断 |
| 恢复 | 旧备份升级；新表真实恢复；恢复任务禁自动执行；当前撤销不丢；模型/费用配置需重新绑定；原始期限不因恢复重置 |

每个纵向结果包含 API、真实服务验证和可操作 UI，不先铺空入口。所有普通开发和本地测试无实际供应商付费。完成这些仍不等于 F01–F08 或 N01–N12 整体完成。
