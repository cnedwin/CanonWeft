# F08 持久引用状态与不可变版本记录

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

继续既有授权和来源收集计划，不启用正式0036清理。

- [x] 将具体材料写入retention_references，保留原始年龄；新增/修改/采用变化推进引用版本，完全相同的重试不改版本或清单修订。
- [x] 每版保存无正文的不可变摘要记录，绑定来源位置/值摘要、观察时间、保留根、生命周期、基准期限；缺失或不匹配的历史拒绝重建，不把过期引用复活。
- [x] 只写入明确PENDING来源关系的版本。当前计算的是自身基准期限，不冒充完整继承期限；完整来源图与财务投影仍是执行前提。
- [x] 资料改变时同事务使旧清单失效；未知/消失引用保留并报告，不能假定已清理。初始写入批量，更新用行锁和精确旧版本条件。
- [x] 真实MySQL覆盖初次/重试、编辑回退、采用变化、账本删除上限、损坏/缺失历史、并发/回滚及跨批写入，更新实际证据。

裁决：新增版本表放入retention_sources.sql.pending，旧过期读取夹具继续使用原引用/证明表，不伪造它们已有新版历史。新登记器不为没有历史的旧引用重新生成“可信历史”。LEGACY_REGISTERED引用的created_at使用登记年龄基线，与first_verified_at相同，不声称知道原文的原始UTC创建时间。
