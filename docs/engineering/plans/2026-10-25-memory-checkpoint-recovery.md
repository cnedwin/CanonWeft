# 私人工作会话保存与恢复实施计划

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

使用既有接口与数据契约开展定向实现和验证。

目标：创作过程中私人短期笔记可安全保存、重试和恢复；服务成功但回执丢失不产生重复会话，旧重试不覆盖后续编辑，多窗口冲突保留本地输入。此功能承接后续分层记忆任务，不替代完整小说交付。

依据：UNIFIED_MEMORY_ARCHITECTURE.md 第七节、AGENTS.md 第7/8/9条、UNATTENDED_NOVEL_DELIVERY.md F09-C。技术栈保持v1.7.1，无付费模型调用。

设计决定：SaveSession新增必填operation_id，复用既有operations事务与匿名化重放机制；fingerprint包含动作、项目、分支、原ID/版本和完整文档。重放返回当前已授权会话而不重新修改。历史会话继续可读；该历史节点未部署过的旧客户端保存必须升级为携带请求编号。新增只读精确会话接口供恢复/冲突核对。登记memory.session收据归属，备份/删除沿用现有表。

Vue在作者/项目/分支隔离的本机暂存保存基线、文稿和未完成请求。请求发送前冻结并持久保存；未知结果只允许按原请求核对，不在修改正文后悄悄生成第二份。明确版本冲突时保留本地输入，展示服务器新版本，作者明确选择后再基于新版本编辑。切换/卸载迟到结果不能覆盖新页面。

审查重点：重放时权限是否重新核对；清理匿名化是否找到正确项目；回执丢失后改变输入是否导致重复创建；恢复稿是否按用户/分支隔离；本机存储失败是否被如实提示。保存成功不代表内容被采用为正史。

## 最终实施与证据

- 创建/修改均有同事务收据；相同编号与输入返回当前工作记录，修改输入冲突，旧修订的新请求仍走CAS拒绝。重放仍校验当前权限、项目分支和作者；没有新表或放宽权限。精确GET接口供冲突对照。
- 初始两项真实MySQL测试分别复现重复创建、并发重复。修复后通过；最终七项记忆集成21.142s通过，覆盖旧提炼/采用/来源隔离回归。真实MySQL备份恢复含memory.session收据，节点5.522s通过（含记忆归档/权限/源损坏子例）。服务和retention单元最终1.953s / 0.427s，相关vet通过。
- 一次限定审查发现两个Important：跨窗口共享暂存key可覆盖未决请求；pending暂存失败却仍发送。两项均先以浏览器失败复现后修复，不重复审查。
- 最终每个编辑器拥有独立本机记录；刷新由当前标签页指针恢复，其他历史稿可明确选择。恢复时复制，清理只移除本编辑器及未被改写的祖先修订；另一个窗口的新稿不会被覆盖。提交前必须成功保存完整冻结请求和恢复指针，暂存失败不会首次发送，恢复后可重试同一编号。
- 本地暂存是未确认输入恢复手段；MySQL仍是已保存checkpoint的权威。浏览器存储被用户主动清理后，未保存输入无法由服务器凭空恢复；未知请求原记录未能保存时明确不发送。
- 八项浏览器交互7.1s通过；另补实际保存迟到跨分支用例2.8s通过，共九项（没有重复运行无关全平台套件）。浏览器使用mock API；数据库/备份为真实隔离MySQL9.7.4。
- Vue类型/lint及133模块构建通过。原业务数据库和主服务没有迁移/重启，下一步仍是分层摘要/增量调度及完整小说，不将此节点当作整体完成。
