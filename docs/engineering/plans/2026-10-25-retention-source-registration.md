# F08 实际来源首次登记与版本记录

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

材料年龄登记沿用既有保留契约。目标是把真实SQL材料的年龄基础持久化；不启用尚未完成读取门禁/归档兼容的0036正式迁移。

裁决：来源列历史与可执行清理引用分开登记。一个JSON列可以同时包含正文、嵌套文件引用和派生来源，不能把列摘要登记冒充完整引用解析。先固定每个来源位置的首次UTC观察和各值版本的首次UTC观察，后续引用/来源图必须复用它们。历史系统时区不明，观察记录标记LEGACY_REGISTERED，不将旧业务时间伪称可信UTC创建时间。

- [x] 实际扫描登记所有属于项目的私密正文/文本/请求键，以及固定目录中实际blob所在的源列；不登记工作区账号、凭据或正文副本。
- [x] 首次观察不可由重复扫描、内容编辑、回到旧内容、重启重置；NULL和空串分别记录，旧摘要版本保留。内部唯一身份不含自由文本主键。
- [x] 在同一事务使用项目锁、当前受保护账本和当前来源读；外部调用必须工作区所有者，返回仅数量。未激活、部分表安装、陌生表/列和跨项目归属拒绝；任何失败整体回滚。
- [x] 精确校验登记表布局和主键，不将额外元数据表默认为安全。新表只在pending DDL，备份/日志/恢复接通前不激活。
- [x] 真实MySQL验证重复/编辑/撤回编辑、回滚、旧事务快照、隔离权限、表漂移与驱动时区；更新记录。

后续：把持久化的来源位置/版本观察接入完整引用收集器，包含所有JSON嵌套引用与派生版本关系；当前观察覆盖不能赋予Inventory.Complete或物理删除权限。原文摘要只用于身份一致性，不赋予外部导入数据执行权限。

## 实施证据与边界

- `retention_source_slots`固定项目/来源列/规范主键和首次观察；`retention_source_values`保存内容摘要、NULL标志与该值首次观察。只有INSERT，不在重试/编辑中UPDATE时间；通过两个新pending表实现，仍未加入正式schema/backup/binlog目录。
- 当前读使用`FOR SHARE`，在读取后取数据库UTC，避免旧事务快照或锁等待前时钟被当成实际观察。DATETIME使用UTC文本读写，独立于驱动Loc和会话时区。不存在把旧业务created_at推断为UTC的逻辑。
- 每500个来源位置最多4条读写语句，仍处于同一事务，历史值查询只取本次实际值，不全量读取所有版本；跨批失败整体回滚。301条实际资料产生超过600条源列观察的批量/重试测试通过。
- 已接Workspace服务和POST `/api/projects/:project/retention-sources/register`。未安装正式迁移时返回503；工作区所有者权限在服务内检查，响应只有计数和观察时间，没有正文、摘要或来源键。正常HTTP全局迁移校验继续拒绝测试中的伪0036标记，**未声称HTTP成功登记已在正式迁移下验收**。
- 8项不同MySQL9.7.4专项分别通过；包含目录漂移的7个子用例、真实HTTP未登录/编辑者/未激活门禁、服务跨工作区拒绝、触发器注入失败的原子回滚、旧快照、UTC驱动、并发首次登记、编辑回退、批量。批量改造后4项相关专项一次通过11.498s；原只读库存HTTP兼容用例通过3.22s。非事务表明确在目录检查拒绝，不能依赖某台数据库后续报错保证回滚。
- 初次组合运行有1项测试误把pending伪标记当成可通过正式HTTP迁移校验的安装；调整测试顺序和证据范围，保留生产门禁。没有改动门禁绕过，也没有付费、正式库迁移或浏览器UI变化。
