# 分层摘要与精确来源实施计划

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

依据UNIFIED_MEMORY_ARCHITECTURE.md L3及F09-C，继续原分支、v1.7.1社区栈和免费执行边界。

目标：已有Recipe可实际生成场景/章节/分卷/全书摘要候选，导入后以结构化层级和精确下层修订持久保存；源变更传递失效，已保存历史仍可追溯。此节点建立真实分层处理链，自动增量排程在其后接入，不宣称完整小说或全书质量验收。

设计决定：memory.Item新增可选summary描述（level/unit_id/title/input pins），不新增表。原始资料仍通过Sources定位；上层摘要可以没有直接原文Sources，但必须有已采用的相邻下层摘要精确版本，递归落到原文。摘要来源是审计关系，不自动变成必须塞入提示词的Dependencies，否则多层压缩会退化为整本展开。层级严格下降且单层最多128输入，整个验证有明确容量边界；旧JSON字段omitempty保持兼容。

服务端冻结资源或记忆来源，模型不得自己提供正文。复用memory-consolidation preset，增加可选summary_target；上层只能输出指定层级摘要，所有选择输入都须有精确引用，计划不能转成已发生事实。结果仍私人候选，作者明确采用。导入后的摘要继承下层可见性、时间、时间线和创作约束；下层变为候选/撤回/改版，受影响上层在读取与生成前失效，不能依靠后台缓存删除保证正确性。

历史下层修订保留并可按权限下钻，retention/备份验证跨层引用归属，不要求历史pin仍是当前版本。Vue提供层级/摘要单元选择、下层已采用摘要选择、候选编辑与来源查看；范围文字明确“选中范围”，小说章节结构尚未接通前不凭空声称覆盖全部章节。

实际边界：摘要单元当前由整理表单命名，尚未绑定待开发小说章卷树；不同候选不会自动覆盖已采用项。自动增量排程待下一节点。来源机械覆盖不等同语义保真/全书文学验收；主服务未受控切换，无真实供应商调用/付费。本节点没有新表；memo最多8192来源节点、单层128输入，未声称整个长篇端到端性能已验收。

风险重点：压缩不能冲淡主线/主题/高光，机械覆盖仅证明引用齐全，意义保真仍需独立审查；摘要旧版本不得漏过源变更；上层不能降低秘密/计划边界；大规模图验证不能无限递归；不伪装已经自动调度。
