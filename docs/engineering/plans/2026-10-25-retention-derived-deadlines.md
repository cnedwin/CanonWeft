# F08 派生材料继承来源期限

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

沿用已授权的执行计划，不调整完整小说范围、不激活正式清理。

裁决：先使真正用于清理规划的 BuildPlan 支持固定来源版本，再接实际来源登记。仅登记每条材料自己的创建时间会使重建索引和上下文复制获得新期限，因此不能先启用这种不完整登记。

- [x] 用生成材料→工作索引→上下文副本的反例重现复制续期。
- [x] 引用携带来源引用 ID、版本、原内容摘要；同一完整清单内解析，缺失、冲突、循环、重复和超限均拒绝生成清理计划。
- [x] 派生期限取自身期限和所有来源期限的最早值；正式作者内容独立保留，不能通过派生关系给运行材料晋升。未结费用的最小账目投影不继承正文清理期限。
- [x] 将来源关系纳入清单哈希，排序稳定且不修改调用方数据；租约仅阻止当前删除，不能刷新期限。
- [x] 定向反例和整个 retention 单元检查通过，更新实际进度。

范围边界：此项提供真实规划器的期限传播，不声称已完成 SQL 来源关系注册、全部读取门禁、GC 或正式迁移。来源关系必须由后续可信扫描/登记器从业务来源构造，不能接受浏览器提供的删除依据。

## 实施与验证

新增 ReferenceSource 和有界无递归的来源图解析，接入 BuildPlan。单清单最多250000引用、单引用4096来源、全图1000000边；12000级链测试通过。来源变更必须匹配原引用版本及摘要，否则阻止该次计划，不能自动改指最新材料。接SQL登记时须保留仍被引用的旧来源期限/版本证明，不能因当前行覆盖而重置原始期限。

6项专项覆盖复制链、10种非法来源、多个来源/本身更短期限/稳定哈希、历史时钟/租约/已过期证明、共享正式对象、长链与项目删除上限。原复制链回归先失败（仅1条到期，应该3条），实现后通过。专项首次组合运行发现fixture自带无首次登记时间的孤儿blob，预期blocked数量多1；移除该纯inline用例不相关的blob后，整个retention包通过0.959s。retention/service的go vet通过。没有数据库结构、HTTP、Vue或部署变化，因此没有重复数据库/浏览器检查；未付费。

下一步：实际来源扫描与SQL注册需写入完整来源关系及不变的首次登记时间，并核对清单覆盖。当前 Sources 可为空以兼容未派生材料，只有可信完整扫描器能够确认是否确实没有来源；本功能不把旧预览扫描自动提升为可执行GC清单。随后接原子断开与物理回收，不再扩展本图算法或重复该历史节点检查。
