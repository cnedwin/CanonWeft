# F08 retention schema-32 contract and first implementation gate

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

**Goal:** expire private runtime payloads on schedule without deleting published content or financial evidence, and produce an exact, concurrency-bound deletion plan.

**Architecture:** authoritative deletion timestamps come from the protected ledger. Retention metadata is a side projection, never a new authority. An exhaustive scanner produces an inventory; a pure policy/planner produces a hash-bound plan; later locked execution detaches actual content references, records an EXPIRED evidence projection, and only then removes exact objects.

**Tech Stack:** Go, MySQL InnoDB, existing LocalBlobs/S3, Vue. No paid calls.

**Spec:** [产品设计](../../FINAL_PLAN.md)、[需求追踪](../../REQUIREMENTS_TRACE.md)。

`reference.id = SHA256(canonical JSON [project_id,owner_table,owner_key,field_key])`. owner_key contains ONLY canonical scalar IDs/revisions/ordinals, encoded as an ASCII canonical tuple; not row content, provider receipt text or actor-provided paths. Hash collisions or inconsistent duplicate rows reject the inventory. Table/field paths come from code catalog. Composite keys must be read with parameters, never interpolated from stored owner_key.

### Shared canonical identity and final row form

Use exported `retention.Rule(fullKey)`, `RowOwnerKey(table,row)`, `PrimaryKey(table)`, `OwnerKey(parts...)`, `DigestKeyPart(text)` and `ReferenceID(project,table,ownerKey,field)`. `field` is local, e.g. `frozen.input_hash`; `Rule` is full, e.g. `generation_tasks.frozen.input_hash`. OwnerKey is `json.Marshal([]string{...})` with no whitespace, exact fixed schema-PK order. RowOwnerKey derives lowercase 32/64-hex IDs or canonical nonnegative int64 decimal according to PrimaryKey's fixed column Kind; free-form key columns always use `sha256:` + SHA256(original UTF-8), even if a particular name happens to look like a 32-hex ID. PrimaryKey returns independent `[]KeyColumn{Name,FreeText,Kind}` copies and nil for an unclassified table. All 63 schema-31 PK orders are tested against actual migration DDL. Adapters must use RowOwnerKey on the original row; an archive-supplied owner_key is not trusted. ReferenceID hashes `json.Marshal([]string{project,table,ownerKey,field})`, including owner_key as one JSON string. Do not build a second encoding in backup. Array reference occurrences require a separately agreed stable item identity before destructive planning; the generic artifacts.hash rule alone cannot uniquely identify several artifacts.

For a whole frozen field `F`, let `W=SHA256(exact original SQL UTF-8 bytes)`. If `F.input_hash=H`, the nested field's payload hash is `SHA256(ASCII(H))`, NOT the hash of quoted JSON. All whole/nested references are extracted from one original locked owner-row snapshot. Each original hash is checked before any field is replaced; one owner update then atomically installs the projection and all expiry metadata.

The final whole field contains exact serialized `ExpiredProjection` bytes `P`:

```json
{"materialization":"INLINE_ENVELOPE","schema":1,"state":"EXPIRED","reference_id":"whole-reference-id","original_payload_hash":"W","expired_at":"T","summary":{"input_hash":"H","estimate_micros":0,"reserved_micros":0,"charged_micros":0,"input_tokens":0,"output_tokens":0,"accounting_revision":0}}
```

The nested EXPIRED reference retains `object_hash=H`, `payload_hash=SHA256(ASCII(H))`; its evidence projection `NP` has `summary.value_hash=H` and the nested reference ID/original payload hash. `ProjectExpired` supports BLOB references using `raw=[]byte(H)` and requires `summary.ValueHash==H`. This projection is stored in retention_evidence, never in the original scalar column. Ordinary scalar columns such as `model_calls.output_hash` remain exactly H, with their matching EXPIRED side reference removing them from the live object closure. For a replaced whole frozen field, backup obtains H only from validated P.summary.input_hash, then validates the nested reference/NP against it. It does not parse P as the old frozen type or compute W from P.

Materialization is mandatory, with three closed forms. `INLINE_ENVELOPE` means exact source column bytes equal the saved projection. `BLOB_REFERENCE` means the original scalar hash remains unchanged and its separate proof contains value_hash; for a nested reference, the validated parent envelope supplies that retained hash. `CLEAR_SCALAR` means an allowlisted non-key short-text source column is exactly empty and the separate projection binds its original bytes and identity. `ClearScalarAllowed(fullRule)` currently permits only source_imports.filename, knowledge_chunks.resource_name and working_chunks.source_name. `ProjectClearedScalar` is the explicit constructor; it still verifies original bytes and expiry. Frozen bodies can never choose CLEAR to evade structure checks. `ValidateProjection` checks storage/mode compatibility; the caller must also apply ClearScalarAllowed to the actual bound field. Empty/unknown materialization and ROW_REMOVED are rejected. First activation retains minimal owner-row shells: no preview/chunk owner-row DELETE is supported. Unique text names or free-text PK values remain BLOCKED until a separate typed deterministic anonymization and safe reference/key conversion is implemented; this intermediate gate is not full F08 acceptance.

Strict archive validation must match fixed row PK→canonical reference ID; owner/table/field; retained original payload hash; expiry timestamp; exact inline projection bytes and their projection_hash; each evidence record's corresponding reference/revision; and scalar/nested value_hash against both object_hash and SHA256(ASCII(value)). EXPIRED without its complete matching proof is invalid, not permission to skip references. This is internal consistency of the trusted expiry transaction, not a claim that erased original bytes can be reconstructed from a digest. Historical frozen/release hashes remain old evidence; new authoritative qualification cannot consume the expired representation.

`ValidateProjection(p ExpiredProjection, storage StorageKind) error` is the shared validation entry point once original bytes no longer exist. It checks schema=1, state=EXPIRED, identity/hash shapes, a nonzero expiry clock and `ValidateSummary(summary,storage)`; it does not establish owner scope, original source truth, permission, or hash-chain authenticity. Backup must still reject duplicate/unknown JSON keys and perform the exact bindings above. `ProjectExpired` verifies original bytes and deadline before using the same validator. Neither function grants qualification.

The closed financial summary preserves `price:{currency}`, `estimate_micros`, `input_hash`, optional `capability:{mode,evaluation_id,evaluation_step_id,suite_hash}`, optional `suite:{policy,version,hash}`, and optional `weekly_grant:{id,schedule_id,revision,week,cap_micros}`. Suite policy is restricted to repository-deterministic-v1/v2/v3 or repository-semantic-review-v1; the currently supported suite version is 1 and hash is mandatory. No suite cases, schemas, names or descriptions are retained. Modes are TRIAL/EVALUATION/QUALIFIED; EVALUATION requires its run ID while old legacy steps/suite hashes may be absent and are checked by the archive's existing origin-specific rules. Week keys are YYYY-W01..W53; revisions are positive and grant caps are 0..10^12. `currency`, reserved/charged amounts, token counts, accounting revision and UNKNOWN remain distinct from frozen price metadata. `content_scope_hash` is a fixed hash-only semantic evidence field; it is not a blob reference. No prompt, suite body, input/output body, model endpoint, credential reference, issue reason or arbitrary JSON is admitted.

Legacy qualification origin proofs require a separate versioned `EXPIRED_LEGACY` conversion managed by qualificationledger/backup. Before detaching frozen bytes, verify the original `legacy-evaluation-ledger-v1` Proof against the original full canonical record. Retain that original Proof and original frozen digest(s), plus the new typed scope/financial projection hash and conversion relation. Never recompute the old RecordHash from the expired summary or re-sign it as the old proof. Retention's `original_payload_hash` is the exact SQL byte digest; any old canonical frozen hash is a separate value and must not be conflated. The archive then validates this explicit conversion relation, not a fiction that original text remains available. No conversion changes UNKNOWN held money or reauthorizes execution. This shared summary API reserves the required typed data; qualificationledger conversion implementation remains integration-owned.

`payload_hash` fingerprints the original field bytes being expired, not necessarily object_hash. For a BLOB reference the object hash identifies the bytes while the payload hash binds the actual source field/embedded structure. Repeated writes increment the reference and project inventory revisions but never reset the original material's birth time. A restored row retains its original source time. For verified UTC records, clock/database copy/file mtime/backup timestamps cannot extend TTL. Historical validation found legacy MySQL sessions used SYSTEM (+08:00) while DSN loc=UTC only affected parsing. Such old source times are explicitly LEGACY_REGISTERED: preserve the original wall-clock value for evidence, start eligibility at the first persisted trusted UTC registration, and never reset first_verified_at on rescan, replay or restart. SOURCE_UTC is allowed only for writes after the verified session-UTC cutover or independently proven UTC evidence. Unclassified time basis blocks planning. Old deletion events with unproven timezone likewise carry LEGACY_REGISTERED and a retained source_deleted_at; cleanup-eligible/online/backup deadlines receive a conservative registration grace, while recover_until remains NULL and recovery access stays denied. The UI must disclose this cleanup grace rather than claim retrospective deadline compliance or restored access. Future T0 deletion writes trusted UTC lifecycle metadata in the same transaction; a restored projects.deleted_at row is never authority to set T0.

`UNSCANNED`, missing catalog coverage, unknown field rule, unknown object state, or partial/mixed schema inventory blocks a destructive plan. Catalog version 1 names all 63 current schema-31 business tables; schema-32's six retention tables are separately projected as metadata and must not recursively register their own plan/evidence bodies. Future tables require explicit catalog review before cleanup. The integration layer must add these six tables to strict backup schema/catalog and migration checks; the pure module does not activate them.

## Immutable-field conversion contract

1. Frozen JSON, old manifests, settlement hashes and source/evidence hashes are not re-signed as though an edited body were the original. Metadata-only immutable bytes may remain. Any frozen JSON that contains request text, messages, context text, tool inputs or outputs is an INLINE private payload and must actually be removed/replaced when due, including future fields. Merely returning Forbidden while retaining online plaintext is insufficient.
2. At expiry, under the same project and owner-row locks as source mutation, re-read the field and compare its hash/revision to the plan. Persist `retention_evidence`, atomically change the reference to EXPIRED, and replace INLINE content with a versioned envelope (below), or remove preview/chunk content rows through an explicit typed handler. Never write arbitrary dynamic SQL based on a catalog string. A metadata-only representation must remain available for history/accounting APIs.
3. EXPIRED envelope: `{schema:1,state:"EXPIRED",reference_id,original_payload_hash,expired_at,summary:{...allowlisted metadata...}}`. The separate projection hash is the digest of those exact canonical envelope bytes. It is NOT the old source hash. Old source hashes remain addressable evidence, not live blob references.
4. Allowed summary keys are typed per source: source IDs, call ID, config ID/revision/hash, original input/output/report hashes, lifecycle state, scope/version IDs, counts, numeric token/cost/duration fields, currency, accounting revision, UNKNOWN status, cancellation and fixed failure codes. No free-form output, reason, issue explanation, metrics detail, request, prompt, context, provider response, key reference or source text. Report verdict/counts may remain without report prose. Score check detail and semantic summary/explanation can contain private text and must not survive in metadata.
5. `generation_tasks.frozen` currently contains hashes/config/price/capability metadata; the scanner must classify the complete typed structure, including nested CapabilityTrial/Manifest data, rather than assuming it never embeds text. `tool_trials.frozen`, `qualification_runs.frozen`, `capability_qualifications.payload`, `qualification_steps.metrics`, `qualification_approvals.payload`, `semantic_review_runs.frozen`, `context_packages.payload`, `generation_previews.content` and manual reconciliation's free-form evidence require explicit content handling. Qualification report blobs may include output bodies; neither publishing nor accepting a review promotes their raw runtime payload to permanent content.
6. model_calls.input_hash is a request/accounting fingerprint, not a blob. Source-column review found model_call_receipts.payload is actually `[outcome,amount,receipt,outputHash]`, including private provider receipt text. It therefore needs a whole-payload typed expiry conversion as well as the separate fourth-item output-hash reference. Preserve original tuple/settlement/receipt identity digests, and retain only fixed state/amount/receipt digest/outputHash/call metadata; never replace the receipt text and re-sign the result as the old tuple. Its output hash ceases to be a live reference after expiry. This converter remains pending, not a hash-only exception. model_call_accounting, numeric budget balances, UNKNOWN reservation, qualification call amounts and reconciliation chain remain; never release/recharge money due to retention. Unresolved accounting stays held past the normal metadata anniversary. Closed numeric audit metadata uses 365 elapsed days; protected deletion/revocation identities have no automatic expiration in this slice. The independent authority ledger currently also copies free-text revocation reasons; their separate privacy conversion is an explicit unresolved requirement, not permission to mutate tombstones.
7. Published/adopted authoring content (正文, IP, necessary artifact references) can retain a shared object. Expiring a raw reference still denies access via that raw execution record, even when another valid content reference keeps the same bytes alive. New qualification cannot use expired raw evidence. Historical qualification displays “原始材料已按期清理”; it cannot masquerade as freshly validated or silently inherited by new work.
   Working-index content/vectors are rebuildable raw copies, never permanent content roots: they can contain previews or frozen runtime input. Expiring them disables/rebuilds the affected derived index while the genuine user-authored draft/source remains retained by its own reference. This prevents an index from keeping expired runtime text alive indefinitely.
8. The integration layer must teach backup/archive validation, blobReferences and log state materialization to understand the EXPIRED representation. Existing manifest/frozen digest checks cannot simply be disabled. An EXPIRED proof must match the original identity/hash and exact transformed field. Old 30/31 backups convert to empty UNSCANNED registry, preserve original source times, never claim already-cleaned content and never restart GC jobs. Restore sanitizes retention_jobs to CANCELLED/restored_disabled, then a fresh current-ledger scan is required before any later cleanup. Existing backup bytes and hash chains are never rewritten in place.

## Current pure planner contract

`DeletedLifecycle(ledgerID, deleteSequence, deletedAt)` computes 7/30/65-day deadlines from already-authenticated UTC evidence. `Deadline(class,born,lifecycle)` uses elapsed UTC durations: candidate/raw 30d, failed media/debug 7d, temporary 24h, backup 35d, audit 365d. Active content and protected authority have no automatic deadline. Deleted project content becomes cleanup-eligible at 7d, while 30d is the completion deadline; original earlier raw expiry still wins. `cleanup_eligible_at` is separate from `recover_until`: legacy registration sets a cleanup grace but leaves recover_until NULL/zero, so it cannot revive recovery access for an old deletion. A future recovery endpoint must prove a trusted T0 within the preceding 7 days and current authorization; absent proof, refuse. This does not implement recovery or change tombstones.

`BuildPlan(Inventory,now)` produces exact references to expire and exact registered object hashes to remove, with canonical inventory hash and revision. It refuses incomplete/unknown inventory and unsafe IDs, preserves live shared references, prevents a raw record being labelled content to evade TTL, retains unresolved accounting, respects bounded leases while reporting overdue cleanup, and does not treat a previous DELETED receipt as a present object. The executor must reload and compare under locks; a saved plan is never permission to delete blindly. Unregistered/orphan files require their own trusted age/ownership registration before planning deletion; disk enumeration alone is not authorization.

Registered objects carry immutable first_seen_at from the first trusted UTC registration and lease_until. A complete inventory with zero references may plan an orphan only after 30 elapsed days from that registration; unknown age is explicitly BLOCKED, and a future first_seen_at is invalid. Object leases may extend at most 24 hours and prevent physical deletion even when all old references are expired. Missing/removed files must still be confirmed by exact-key BlobGC. Any PRESENT object after a deleted project's online deadline is reported overdue, including orphans still waiting for grace or blocked leases. Rescan, restore or file mtime must never reset first_seen_at. Before live activation, all cooperating blob writers/new-reference attachments must coordinate under the project/object lock or register a bounded lease and bump inventory revisions; no physical deletion is enabled before those hooks are wired.

## Review focus

- All runtime copies of the same private output must expire, including metrics/preview/report and frozen context; field name alone is not enough.
- Published content roots must be based on actual graph reachability, not a client boolean. The pure planner's ContentRoot input is trusted scanner data.
- State from a restored backup cannot override current protected deletion or authorize destructive replay.
- New writers, cleanup and recovery-copy leases must share project/object locking and revision checks; expiry does not imply immediately successful physical deletion.
- Unknown cost and retained audit hashes are metadata; retention cannot settle, release or re-dispatch a call.

## Narrow storage GC gate (2026-10-25)

`storage.BlobGC` is separate from ordinary `BlobStore`; it only accepts an exact lowercase project ID and content hash and returns REMOVED/ABSENT after verification. No list/prefix/project-tree deletion method exists. New `blob_gc*.go` files implement the capability without changing existing blob read/write methods.

- Local: constructor requires an existing absolute nonlinked root and binds its directory handle. Deletion binds and validates the project directory, checks a regular bounded file and its content hash/inode, unlinks only that exact file, then confirms absence. Missing targets are idempotent; errors expose no content/path. Caller still must hold business/object locks and compare plan revisions.
- S3: same exact key, bucket-versioning preflight, verified bounded object bytes and ETag, conditional `If-Match` DELETE, exact-key NoSuchKey confirmation, and a second versioning check. Enabled or Suspended versioning is BLOCKED: this non-enumerating API cannot erase historical versions and never calls a delete marker “physical deletion”. No governance/retention bypass. Denied/unknown/missing-bucket errors are not absence.
