# 增量摘要重整闭环

> 历史工程方案：保留技术决策、接口与验证设计；文中的迁移版本和计划状态仅适用于对应历史节点。当前实现状态见[实现状态](../../IMPLEMENTATION_STATUS.md)，当前版本见[版本基线](../../COMMUNITY_STACK_BASELINE.md)。

继承已授权设计与社区基线。先做能够真正更新原条目的重整闭环，再接小说发布后完整自动执行策略，不重复分层摘要验收。

设计：读取当前已持久化记忆和来源构建可恢复的待处理视图，不增加第二套任务权威。过期摘要按层排序；下层未确认/过期则等待，下层采用后自动可重整。Recipe负责实际执行记录、重试与费用。summary_target可携带原item/revision，服务端验证单元、层级、时间线和作者权限，准备/dispatch全过程重验；导入一次只能选择一个替换候选，原ID保持、生成新修订并等待作者采用，不悄悄替换正史。幂等重放返回已导入的当前编辑版本。

原有固定核心标记、控制属性、依赖、可见范围与有效期不可在重整时丢失；新来源更严则拒绝放宽。历史仍可追溯；旧上层pin在其自身重新整理采用前仍失效。任务视图由权威表派生，备份恢复后可重建，实际Recipe按已有恢复禁用策略处理。

实现补充：固定摘要过期时，专用critic修复上下文仅排除目标及其上层摘要，其他硬锚点/依赖保持。context manifest与缓存键携带refresh目标，原始修订集合参与失效；普通生成不得使用，只有匹配服务器Recipe步骤的整理任务可消费。来源权限在准备前预检。导入同事务写memory.update类型的专用收据，允许已生成/已导入记录正常完成审阅，不允许另一个旧任务借此继续执行。现有operations归属/备份规则覆盖该收据，无新表。

证据：6项实际MySQL9.7.4提炼/分层/重整集成20.283s通过，另1项来源由公开改为作者秘密的准备前拒绝4.697s；memory/service/presets/retention单元及相关vet通过。9项原记忆/恢复浏览器通过；3项摘要/重整浏览器最终3.7s，包含main与past时间线和旧待办刷新拒绝。原生option的disabled由属性和快照确认，换为实际DOM属性断言，未用放宽业务行为规避失败。Vue types/lint/build133模块通过。

一次限定审查发现“导入后无法完成Recipe”与“非main时间线无法重整”两项，分别真实数据库/浏览器反例失败后修复。无付费、没有重启业务服务。这个节点的自动部分是识别、排序和条件恢复；新章节首轮提炼与授权后的后台执行仍必须在小说发布编排中实现，不能称全自动调度完成。

边界：本节点默认不自动调用收费模型，任务视图也不虚称后台已有实际模型执行。小说章卷树、新章节发布首轮提炼、配置授权后的后台增量执行在后续发布编排中接入，仍属完整交付范围。无费用授权先完成全部免费实现和替身测试。
