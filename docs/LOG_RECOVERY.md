# 数据库日志与恢复：当前实现边界

文档核对：2026-10-28。本文定义专项契约与验证边界；当前工程实现、安装和资格状态见 [实施状态](IMPLEMENTATION_STATUS.md)。

受限 MySQL 事务读取器、快照位置绑定、脱敏日志与附件保存、持久提交记录、指定完整提交点的隔离恢复、自动采集和中断续接已有工程实现。后台专用账号与界面流程保留隔离库验证记录；实际服务、保留清理及恢复采用状态见 [实施状态](IMPLEMENTATION_STATUS.md)。一致快照继续作为回退，小规模演练不授予规模或独立介质灾难恢复资格。

## 已实现的读取边界

- 仅连接本机 MySQL，使用预先确认的 server UUID，并在实际读取连接中校验身份。认证、配置检查和读取使用同一连接；取消关闭该连接，关闭时不创建额外连接，不发送 KILL，不自动重试请求。
- 要求 ROW、完整行图像和字段元信息、CRC32、无部分 JSON 和事务压缩。实际历史日志的格式头也必须为 version 4 / header 19 / CRC32，不能仅相信当前服务器配置。
- 仅输出完整提交的事务，校验字段顺序与主键；回滚和目标位置之后的修改不会进入指定区间。跨日志文件轮转必须连续，无法识别的事件、DDL、损坏或丢失位置会失败，不能据此声称连续保护。
- 空区间必须是同一连接实际观察到的当前完整边界；不能用不存在或猜测的历史位置更新保护时间。并发提交使边界推进时，这种空区间请求会拒绝，收集方应重新观察并读取实际新增区间。
- 部分 JSON 和其他不支持的事件在调用第三方载荷解码器前拒绝。返回固定错误类别，不转发可能含原始内容的依赖错误，也不重定向进程标准输出。
- 单事件 16 MiB、待提交事务 64 MiB、源行数量 100000 的保守上限。网络库会先读取协议包，因此这些限制不是对恶意数据库服务器的内存隔离承诺。
- ENUM/SET 使用完整表元信息将编号映射回文字；保持 NULL、空值、数字标签及 SET 第 64 位。缺少标签、越界或展开超出容量时拒绝。

固定依赖为 `github.com/go-mysql-org/go-mysql v1.16.0`，仅使用其客户端认证与事件解析；连接生命周期和受限读取由本项目控制。数据库启动配置增加 `binlog-row-metadata=FULL`；停止并重新启动本地实例后，已实际查询确认为 FULL。

## 本地验证证据（历史定向结果）

2026-10-25 完成独立代码复审、12 项解码单测和静态检查。可控协议端点验证握手、预检、设置、读取四个阶段的取消、单连接关闭、不发送 KILL、部分 JSON 不向标准输出泄露，以及历史格式和 CRC 拒绝路径。

真实 MySQL 8.4 回归使用独立随机数据库，验证提交/回滚、目标边界、错误源身份、空区间、实际轮转、位置缺失与数值保真。覆盖 uint64 最大值、DECIMAL(65,30)、JSON 大整数、微秒日期、负时间、二进制和 NULL/空值；JSON 比较仅去空白，不经浮点转换。最终协调门禁通过，未重置项目数据库或删除源日志。

## 已验证的日志仓库与恢复

- 短暂全局读锁内绑定一致快照和日志坐标；重设 REPEATABLE READ，避免 FLUSH 的事务边界让 READ COMMITTED 会话产生混合快照。正文与附件读取阶段已释放全局写锁。失败时丢弃物理连接，释放事务和会话锁。
- 基线与元数据一起提交为校验过的不可变文件。事务段只有完整行、来源、链前驱和所需附件；排除密码、会话、密钥引用及可复活的执行权限。
- 每段日志有独立提交凭证。最后一段或所有日志载荷丢失时会失败，不会静默退回旧恢复点；进程在载荷发布后退出，重开时仅为已验证完整链补齐凭证。
- 每个中间提交点都检查数据、完整导出包、清单和条目容量，历史附件另有累积字节和数量上限。空间不足拒绝新增，已承诺恢复点仍可读取；为提交凭证预留容量。
- 每个已验证基线按源快照时间保留 35 天，复制文件不会刷新寿命。一个坏文件或 Windows 占用不会阻塞其他可清理基线；失败保留所有权以便重试。基线损坏导致年龄无法可信读取时保守保留并显示清理异常，不能声称这类残留也已自动清除。
- 自动采集按源观察时间判断新鲜度。每日切换先持久记录衔接意图，新基线保存后再补齐旧链到新坐标；中断后补采或明确记录缺口。启动及每日审计检查所有未过期的当前结构版本链，历史错误不被较新健康基线隐藏。

持续写入现在按完整事务分段保存，同一实际观察区间可超过 1000 次提交；只有已持久提交的前段可以推进恢复位置。真实 MySQL 验证了 1005 次提交、第二段保存失败、已保存前段后取消，以及重开续接（3 场景共 21.081 秒）。单事务和总历史对象容量限制仍有效，不能将分段解释为无限存储。

结构 30 → 31 的新增三表有显式可信转换：旧日志继续绑定原有 30 版本、迁移校验和及完整行合同，恢复时才补三张空表。纯测试验证旧基线回放、混合版本拒绝及精确容量边界；实际 31 数据库的语义审查备份与恢复验证了输入和报告保留、待执行审查取消、所有旧审查禁用（8.488 秒）。这不表示所有未来结构变更自动兼容；每次迁移必须补充映射与验证。结构切换无法证明的连续区间记录为缺口，旧的已验证恢复点仍然可用。专门演练从真实源快照构造准确的旧30表结构夹具，验证新31运行器保存切换缺口、新建基线、旧点再恢复到真实31数据库（7.432 秒）；它不冒充使用旧二进制进行在线采集。

事务顺序由日志位置决定。秒级事件时间不得将后续恢复点回退到已经观察过的基线之前，也不超过区间的源观察时间；同一末端位置的两种导出路径保持一致。已完成复现、回归和独立复审；原始提交时间仍保留，不伪造更高精度。

真实隔离 MySQL 演练覆盖：中间正文和对应附件恢复、排除后续附件、禁止旧身份/密码/会话启用；采集后重启续接；真实尾段丢失告警与新基线；日切新基线发布后取消再启动；旧链损坏但最新基线健康。最新七项门禁全部通过（32.849 秒，测试规模）。Windows 另实测进程直接退出后的锁释放、文件占用导致删除失败后的独立清理和重试。不能将这些耗时当作长篇小说或 35 天日志的 RTO。

专用采集账号采用本机独立凭据，业务表只读，具备读取日志、查询坐标和短暂建立一致边界所需的权限。MySQL 8.4 的全局读锁可以使用较窄的 `FLUSH_TABLES`，不需要授予完整 `RELOAD`；日志读取仍是服务器级权限，程序只持久化目标库的脱敏内容。参考 [FLUSH 官方说明](https://dev.mysql.com/doc/refman/8.4/en/flush.html)、[权限官方说明](https://dev.mysql.com/doc/refman/8.4/en/privileges-provided.html)。真实随机库验证了实际读取、写入/DDL/额外权限拒绝、授权中断后的原密码恢复（6.798 秒）；`studio_test` 账号初始化两次保持相同密文，正常环境加载后的权限审计通过。这些历史测试本身不创建或证明实际 `studio` 账号；正式启动器会在启动前初始化/复审该账号，当前服务状态见 [实施状态](IMPLEMENTATION_STATUS.md)。

2026-10-25 只读探测发现本地数据库会话默认使用系统时区，`NOW()` 比 `UTC_TIMESTAMP()` 快 8 小时；Go 的 `loc=UTC` 只改变解码，不能改变 SQL 默认时间。运行连接现显式设置 UTC，新池连接的实际只读测试通过；本地数据库启动也明确指定 UTC。已存储的 DATETIME 字面内容和历史恢复包不批量转换，日志位置与源 UTC 观察时间继续决定恢复边界。涉及遗留数据的期限登记必须保守标识时间依据，不能假定所有历史字段已经是 UTC。参考 [MySQL 时区说明](https://dev.mysql.com/doc/refman/8.4/en/time-zone-support.html)。

停机演练发现并修复 Windows MySQL 监控父进程退出后数据库子进程仍存活的问题。当前以程序路径、显式数据目录和监听进程共同确认归属，使用正常 shutdown，新增启动指定 `--no-monitor`，验证就绪后才保存 PID。实际演练确认基础服务重新可达，普通启动拒绝不完整测试凭据状态，专用初始化恢复同一密文后正常加载。重启后全局/会话 UTC 偏差为 0。验证脚本以自身进程退出为完成条件，不能因继承的输出句柄把后台服务寿命计为测试运行时间。参考 [MySQL Windows 进程说明](https://dev.mysql.com/doc/refman/8.4/en/server-options.html#option_mysqld_no-monitor)。

真实浏览器四项验收通过（2.5 秒）：保护页切换不丢未保存名称、历史缺口/过期/请求失败不展示虚假正常、专用账号自动采集显示真实源覆盖时间、owner 诊断下载只包含白名单元数据。浏览器验证须等待已登录页面再读取保护接口；登录完成前的 401 不得通过放宽产品认证规避。诊断实际 SQL 测试另验证当前工作区隔离、禁用/非 owner 拒绝和导出审计；诊断不保存一份含正文的服务器副本。

恢复入口、受控启用及保留期清理按现行 F08 流程管理，实际工程覆盖见 [实施状态](IMPLEMENTATION_STATUS.md)。每次后续结构变更仍须逐次验证兼容；实际 RPO/RTO、长期保留规模、独立介质与受保护撤销账本的灾难边界单独验收。恢复不得启用旧身份、密钥、任务或已撤销能力。上述本地专项验证未调用付费模型。
