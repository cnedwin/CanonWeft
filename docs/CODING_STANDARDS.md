# 统一 IP 创作平台编码与交付规范

规范版本：1.7。维护日期：2026-10-28。适用：`novel-studio`及后续接入的漫剧、游戏模块。

正式技术栈为 Vue 3 + TypeScript、Go / Echo v5、MySQL。本规范约束 `backend/`、`web/` 的实际新栈实现；[技术栈迁移方案](STACK_MIGRATION.md) 规定迁移步骤与验收。React/Python/SQLite 旧实现只作为迁移行为基线及必要修复对象，不继续扩展两套业务实现。当前实施证据见 [实施记录](IMPLEMENTATION_STATUS.md)，完整底座与小说功能尚未整体验收。

“必须”表示数据、费用、权限或交付正确性的约束；“建议”是可据上下文调整的默认写法。当前需求仍是单人、Windows、本地优先、小说先用，不能以执行规范为由扩大成团队级平台建设。

范围基线为 [v1.1 完整需求与五期方案](DELIVERY_ROADMAP.md)。所有变更关联 [需求追踪表](REQUIREMENTS_TRACE.md)；不能以单人开发或先跑通为由删工序、改质量门或把小说支撑延后。

## 1 开发顺序与范围

1. 先核对需求追踪、`docs/ARCHITECTURE.md`、相关代码和[实施状态](IMPLEMENTATION_STATUS.md)。
2. 一次完成一个可操作的结果；先明确输入、输出、状态变化和失败处理，再修改代码。
3. 实际模型调用、购买或新增资料外发必须由部署者明确启用，并符合目标供应商、数据范围和预算配置；开发或测试开关不能隐式授予这些权限。
4. 功能修改先写能复现缺陷或业务约束的测试，观察失败，再实现并验证。纯文档、排版、低影响可逆变更无需虚构测试。
5. 每次交付留下可运行代码、实际验证结果、需求 ID、已知边界与下一步；不交只有接口名、空页面或固定样例冒充的功能。单章成功不等于完整小说。

## 2 模块与目录

下列是新栈职责边界；已存在的代码按这些边界增量演进，后续目录按真实功能建立，不预建空壳。

| 位置 | 应承担 | 不应承担 |
|---|---|---|
| `web/src/` | Vue 交互、正文临时状态、显示与导航 | 权威事实、预算决定、持久保存 API 密钥 |
| `backend/cmd/studio/` | 配置、依赖组装、启动与关闭 | 提示词、SQL 和业务规则 |
| `backend/internal/httpapi/` | 请求校验、会话、错误映射 | 直接操作跨模块业务表 |
| `backend/internal/domain/` | 类型、状态机、证据与纯校验 | 网络、数据库连接、前端细节 |
| `backend/internal/service/` | 用例、权限与提交边界 | 在事务中等待模型 |
| `backend/internal/storage/` | MySQL 查询、事务、版本与预算约束 | 静默覆盖历史正文 |
| `backend/internal/worker/` | 固定流程、阶段、取消与恢复 | 让模型自行跳过关卡 |
| `backend/internal/provider/` | 外部协议、超时、结构化响应与用量 | 决定正史、绕过费用预留 |
| `backend/internal/skills/`、`presets/` | 版本化方法、示例与角色配置 | 任意脚本执行权限 |
| `backend/internal/backup/` | 一致快照、校验、隔离恢复与撤销 | 导入包直接覆盖正式库 |
| `backend/migrations/` | 有版本和校验和的显式 SQL 迁移 | ORM 自动修改正式 schema |
| `web/tests/`、Go 测试文件 | 可复现行为和回归 | 正式数据或未经授权的付费调用 |
| `docs/` | 架构、规范、决策与交付记录 | 与代码脱节的完成声明 |

调用方向为 HTTP → 应用服务 → 领域与存储/模型边界。接口在实际使用它的模块定义，优先少量业务接口；不要为每张表生成无业务价值的抽象层。媒体模块经共享契约协作，不直接改别的模块的表。

## 3 命名、排版与注释

- 标识使用有业务意义的英文；作者界面与错误提示用中文。
- Go 包名简短小写，导出标识 `MixedCaps`，非导出标识 `mixedCaps`；文件名小写并可用下划线。格式统一由 `gofmt` 决定。
- Vue 组件与 TypeScript 类型使用 `PascalCase`，函数和变量使用 `camelCase`，组合式函数用 `use` 前缀。API JSON 保持现有 `snake_case`，用 Go struct tag 显式映射，不无迁移改名。
- 源文件和正文使用 UTF-8；兼容 PowerShell 5.1 的含中文脚本用 UTF-8 BOM。不得规范化正文后仍沿用旧 hash 或锚点。
- Vue/TypeScript 默认 2 空格，由 Prettier 统一。新增逻辑使用多行结构；函数约 60 行、文件约 400 行是职责审查提示，不是硬拆分标准。
- 注释解释原因和业务边界，公开接口说明副作用。待办写明当前可用路径，不以空函数冒充完成。
- 新栈配置 `gofmt`、`go vet`、ESLint、Prettier 和 `vue-tsc`。尚未创建和执行的检查不得报告已通过。

## 4 Go 与领域类型

- 确定结构使用 struct、明确枚举与版本化 JSON Schema；新网络边界不持续扩大 `map[string]any`。金额使用有明确单位的 `int64`，检查转换和计算溢出。
- HTTP 输入限制体积，校验未知字段、必填字段、取值范围和 JSON 后多余内容。模型输出先校验结构，再校验证据与语义；解码成功不等于可入正史。
- 业务失败返回类型化 error，使用 `errors.Is/As` 和 `%w` 保留原因；不用 panic 表示正常冲突，不吞错返回成功。最外层兜底不泄露密钥或正文。
- `context.Context` 显式传递超时和取消。后台任务独立于浏览器连接生命周期，取消状态必须持久化；不要用每次 HTTP 请求的 context 控制整个章节任务。
- 每个进程维护受控的 `sql.DB` 连接池，启动时 `PingContext`，设置连接数和超时；查询后关闭 rows 并检查 `rows.Err()`。sql.DB 不是单连接。
- 用 `BeginTx` 和同一个 `sql.Tx` 执行事务内全部操作，defer Rollback 并显式检查 Commit 错误。禁止事务内改用 sql.DB 读写同一业务状态，禁止手写 BEGIN 混用驱动事务。
- Commit 回执丢失先按操作 ID 对账，不能假设失败或盲重试。死锁只重试明确回滚且幂等的本地事务，不把外部模型请求一起重做。
- goroutine 明确生命周期和退出责任，关闭时停止接受新任务并保存阶段。mutex 只保护进程内状态，不能替代 MySQL 行锁与版本条件。
- Go string 长度默认是字节；正文锚点按 Unicode code point，以 rune 语义处理。hash 始终使用未经改写的原始 UTF-8 字节。
- 领域检查尽量无 IO；时钟、随机数和外部模型通过可替换边界传入。不得在业务层依赖 HTTP 对象。

## 5 Vue、TypeScript 与前端状态

- 使用 Vue 3、Composition API 和 `<script setup lang="ts">`，保持 TypeScript strict。props/emits、角色结果和 API 返回有明确类型；网络不可信输入先用 unknown 并校验。
- 不用大范围 any、ts-ignore 或强制断言掩盖缺失字段。项目列表摘要与项目详情分开定义，防止把摘要当完整章节对象。
- Pinia 保存跨页面共享的项目与任务元数据；未保存正文和其基础版本留在编辑会话，后台轮询不能覆盖。
- UI 展示服务端认可的状态，不能把候选直接设成正史或以禁用按钮代替后端权限与版本检查。
- 异步结果核对项目、章节和编辑会话代号，配合 AbortController 阻止旧响应污染新页面。历史 ready 不能反复抢回旧章。
- onUnmounted/watch 清理定时器、监听与订阅，保护重复提交、切换、关闭、重试中的未保存输入。
- 表单有 label，状态和错误可读；正文按文本渲染，不对未经净化的内容使用 v-html。
- 正文、提示词和密钥不放 URL；密钥不写 localStorage、Pinia 持久化或日志，仅发送至受保护的本机服务。
- `.vue` 类型校验使用 vue-tsc；仅运行 tsc 不能替代 SFC 检查。开发代理不放宽正式服务 Origin 校验。

### Echo v5 边界

采用 `github.com/labstack/echo/v5`，当前 `backend/go.mod` 锁定 v5.4.2。Echo 仅用于 HTTP 和启动组装，不进入领域、数据层和 Worker；不把 `*echo.Context` 留给后台任务。使用独立 DTO、严格 JSON 解码和显式校验，不能把框架 Bind 当成领域验证。详情见 [框架选型与专项验收](FRAMEWORK_DECISION.md)。

HTTP 测试通过真实 Echo 路由与中间件；API 不存在时返回 API 错误，不能落入 Vue SPA 回退。继续保持 Host/Origin/令牌验证，流式响应如启用则单独配置超时和断线清理。

## 6 API 和错误契约

新增接口先定义：路径与方法、请求类型、响应类型、项目范围、权限、版本条件、幂等策略、错误、是否可能产生费用。

示例为现有接口形状，不是新 API：

```http
POST /api/candidates/{cid}/confirm
X-Studio-Token: <本地会话令牌>
Content-Type: application/json

{"expected_revision": 3}
```

请求必须验证候选所属项目和当前版本，服务端重新执行核心检查。不能接受 `approved=true`、`reviewed=true`、`actual_cost=0` 等客户端字段作为权威证明。

新版当前使用 `{"error":"中文说明"}` 错误体，参数错误 400、未登录 401、权限拒绝 403、版本/预算冲突 409、运行前提不可用 503；未分类服务错误为 500，不能回显内部正文或凭据。旧栈的 422 / `detail` 仅是迁移对照。扩展为 `code / message / request_id / details / retry_policy` 时须同步 UI 与测试，不混用两套信封。可恢复错误要区分“安全重试”“需刷新版本”“需对账后决定”，不能给所有错误统一重试按钮。

读取接口不得隐式生成内容、执行修复或触发费用。新增有副作用的接口应支持客户端操作 ID 去重；现有创建/任务/发布使用各用例的操作 ID，文件上传使用 `Idempotency-Key`。这不代表所有 POST 都可通用重试，SDK 必须按具体接口的版本条件与对账契约处理。

## 7 数据库、内容文件与迁移

必须遵守：

1. SQL 值使用参数绑定；动态表名只能来自代码固定白名单，不能来自用户输入。
2. 正文先生成不可变文件并校验，再提交数据库引用。发布事务同时维护正文指针、账本、版本与必要索引。
3. 版本比较和权威写入位于同一事务；禁止“先检查版本，稍后无条件写入”。
4. 不在事务中调用模型、下载文件或等待子进程。事务内所有数据访问使用同一个 sql.Tx；禁止嵌套调用另开连接的存储方法。
5. 所有项目相关查询明确限定项目；后续加入分支、撤销、时间条件后同样强制携带。
6. 同一实体改名不换 ID，两个同名实体不合并 ID。`revision_id`、项目 `revision` 和正文 hash 各有含义。
7. 派生索引可重建，不能成为唯一原始数据。摘要更新必须绑定原文版本，旧摘要不得混入新确认状态。
8. 未引用 blob 可以暂留，不能未经引用检查就删除。清理前检查正式稿、历史稿、候选、任务与保留备份的引用范围。

新 MySQL 版本从首次建库起提供正式迁移：备份 → 检查 schema_version → 有序升级 → 完整性检查 → 记录版本 → 启动。保留老版本数据库样例，验证 ID、正文哈希、账本和恢复语义不丢失。遇到高于当前程序支持的 schema 版本要拒绝写入。

表使用 InnoDB、utf8mb4；ID 列使用明确区分大小写的比较规则，时间统一 UTC DATETIME(6)。正史提交锁定项目行并检查 expected_revision，预算预留锁定预算账户行；所有权威条件在同一事务内重新检查。

迁移使用版本号与校验和，不在正常请求内执行 DDL。MySQL DDL 可能隐式提交，不能假定多个 ALTER 可随业务事务一起回滚；提供备份、失败恢复和维护模式。应用使用专用最小权限账户，不使用 root，不把凭据提交入库。

不能用修改 `CREATE TABLE IF NOT EXISTS` 冒充已有数据库已经升级。降级需要兼容说明或从备份恢复；不要擅自删列重建正式库。

## 8 证据、正文与故事状态

- 事实、信念、陈述、意图、假设和资源记录分开；“角色 A 说 X”不证明 X 为真。
- 每条证据包含固定原文修订、引文与区间。区间规范为 Unicode code point 的 `[start,end)`；Go byte/rune 与 JS UTF-16 索引不同，前端定位要显式转换或按经过验证的原句定位。迁移必须覆盖中文、emoji 和换行。
- 当前唯一引文可本地重新定位；重复引文必须给出正确位置。不得拿“另一段意思相近的句子”替代原始证据。
- 人工修改正文生成新版本，旧审查与账本不能直接沿用。新的账本必须基于实际修改后的正文独立抽取。
- 作者知道的秘密不等于角色知道。知识检索的权限范围与故事视角范围分别校验。
- 自然语言语义检查不是数学证明。保守检查可能误拦混合对白；应允许修正证据并复核，不能以关闭全部检查解决。
- 资源数量、伤害、能力条件等只有进入类型化模型和验证器后才能声明确定性保证；文本 predicate/value 不等于已实现数值守恒。

## 9 模型调用和费用

必须实现 OpenAI、Anthropic Opus、DeepSeek、Qwen、Gemini 五家适配器与后台配置，不能只提供品牌选择框。完整字段、凭据和能力差异规则见 [模型与小说入口契约](MODELS_AND_NOVEL_ENTRY.md)。连接凭据写入独立加密库；业务数据库、任务、Temporal 和项目备份只含引用，密钥写接口绝不回显原值。保存 Key 不触发收费调用。

- 所有真实模型请求必须通过统一适配器和费用预留路径。测试、后台作业、重试和 Skill 评测都不能绕过。
- 默认关闭付费。密钥存在、额度数字存在，都不等于用户已经授权实际调用。
- 一次章节任务的角色调用共用任务费用范围。不能通过拆角色、重新命名任务或重试清空已花费用。
- 请求前限制输入规模和最大输出，记录价格版本，原子检查并占用预算。网络请求发生在预留提交之后、数据库事务之外。
- 回传总输出用量应包含供应商计费的推理 token；不要自行扣掉缓存、优惠或推理用量后宣称更低成本。
- `done` 调用保存结果与用量；结果未知保持占用并阻止自动重复。HTTP 状态与错误码是否意味着未计费，要按供应商契约判断；当前简单 4xx 分支的局限不能推广到所有供应商。
- 取消是禁止后续步骤，不是撤销已发送的收费请求；停用预算在下一个收费步骤前再次检查。
- 新栈金额统一用整数微人民币单位（1 元 = 1,000,000），价格与汇率有版本。旧浮点费用迁移保守转换并保留原始值，同时处理账目、预留、显示和配置，不能混合单位。
- Provider 输出统一为数据、响应 ID、输入/输出用量、完成状态。schema 不符时保留结果，不把未完整输出当成功作品。
- 不把上下文或生产素材发到新的供应商做“免费测试”；资料外发目的地变化需要遵守用户已授权范围。

## 10 任务恢复、并发和幂等

任务状态改变必须由程序校验允许的前置状态。UI 文案、模型回复或返回 200 不能替代状态机。

每阶段记录至少任务、阶段、输入哈希、使用版本、调用状态、结果和错误类别。成功结果可复用的前提是输入与执行配置相同；未来扩展缓存键时必须纳入模型、schema、工具和 workflow 版本，不只比较自然语言提示。

恢复规则：

- 已完成：读取已有结果，不能为了刷新 UI 重做收费步骤。
- 未开始：重新检查版本和预算，再调度。
- 正在请求但无确定结果：标记 unknown，停止自动重发。
- 已取消：拒绝后续阶段和晚到候选写入；用量记录仍可结算。
- 基础版本变化：不继续向新正史提交旧任务；保留结果供基于新版本复核。

新栈使用 Temporal Go SDK；Workflow 必须可确定重放，IO 放 Activity，历史只传引用/hash，按卷章分段。业务库保存预算、调用、幂等与发布记录，不维护第二调度中枢。收费 Activity 默认最多一次尝试，未知先对账；本地可重试操作也必须幂等。程序锁不替代版本/generation 校验；取消后的晚到结果拒绝，NPC 短请求不排入内容生产长队列。

新增跨模块事件采用事务 outbox 和消费者去重。领域提交与事件生成不能拆成两个可能只成功一个的操作。冻结产物只接收影响提示，不直接改写。

## 11 Skill 与 Agent 编写

每个开放角色至少包含：使用条件、输入、输出 schema、专业方法、正常例子、关键反例、能力边界、失败处理和可观察结果。名字和角色描述本身不算能力。

必须满足：

- Writer、Bookkeeper、Critic 使用独立角色输入；不能只让 Writer 自评自己提供的账本。
- 固定程序决定预算、循环次数、取消与提交；不得把“请勿超预算”放进提示词后移除程序检查。
- 内置方法与项目派生方法有独立版本；运行任务固定快照，方法编辑不改变正在执行的输入。
- 原则、示例、输出格式各有单一维护源，减少互相矛盾。保持专业方法具体，不用长篇泛化口号替代步骤。
- 外部抓取内容按不可信资料处理，记录来源版本、许可、依赖和哈希；不得执行文档中的命令、泄露本项目资料或自动购买依赖。
- 发布评测至少包含正常任务、事实/信念混淆、重复证据、秘密泄漏、格式失败和旧版对照。文学质量不能只靠字符串存在检查。
- 没有真实模型评测的编辑版本标注未验证效果，不能虚构“已通过”。评测需要收费时使用明确授权的专用预算。
- 修改可执行工具属于代码变更，需测试和能力白名单更新；不能通过改 Skill 文本取得任意 Shell 权限。

能力发布、评测、精确用途启用和撤销使用[资格契约](CAPABILITY_QUALIFICATION.md)。保存方法版本与取得资格分别记录；八个内置预设及其普通规划、首章试写无需先完成600次资格评测。正式独立审稿与发布仍须有效的精确用途资格和当前版本审查，不能沿用普通试写入口绕过质量门。

## 12 文件、备份、删除和恢复

- 用解析后的路径校验目标在预期目录内。压缩包拒绝绝对路径、上级路径、重复条目和不允许的文件类型；限制压缩与解压大小。
- 新栈以同一 InnoDB REPEATABLE READ 一致读取事务导出类型化记录，再打包不可变正文与清单；禁止复制运行中的 MySQL 数据目录冒充应用一致备份。备份期间禁止 schema 变更，引用清理保护备份所用文件。旧栈 SQLite backup API 仅用于旧版本保护与迁移读取。
- 恢复前核对清单、正文 hash、结构和引用；恢复到新项目/隔离位置，验证成功后再可见。当前恢复流程仍需进一步加强完整崩溃原子性，修改相关代码时优先补失败注入测试。
- 当前管理目录不被备份恢复覆盖。合并撤销记录后再判断能否恢复；不能通过还原旧数据库恢复被撤销项目。
- 原项目和恢复副本身份独立。删除副本不能偷偷撤销原项目，这是必须保留的回归测试。
- “删除记录”“排除检索”“清理未引用文件”“物理安全擦除”是不同能力，界面和文档不得混称。
- 自动备份必须先成功保存并校验新包，再按保留策略清理旧包；磁盘不足不能先删最后一份可用备份。

## 13 错误、日志与隐私

给作者的错误说明具体恢复动作，例如“项目已更新，请刷新后重新审查”，而不是只显示堆栈或“失败”。开发日志记录错误类型和关联标识，避免把完整小说、提示词、密钥或外部原始错误体默认输出。

日志契约字段：`time / level / request_id / task_id / project_id / stage / error_code / duration_ms / input_revision / response_id`。具体覆盖以实际实现和[实施状态](IMPLEMENTATION_STATUS.md)为准，不由字段清单推断已具备完整可观测性。

HTTP 失败、业务失败、质量未通过、结果未知应区分。失败保留用户编辑内容，不能执行清空或覆盖来“恢复正常”。

## 14 测试策略和验收矩阵

测试重点是会导致错误行为的分支、边界和副作用，不追求用大量“字段存在”测试制造覆盖率。只在外部模型/供应商边界替换传输，数据库、文件、费用和任务逻辑使用真实实现。

| 改动类型 | 必要验证 |
|---|---|
| 正史、版本、证据 | 正常提交、旧版本拒绝、原文不匹配、账本类型、事务失败 |
| 调度或模型 | 阶段结果复用、未知结果不重发、调用中取消、格式失败、费用关闭 |
| 费用 | 已花+预留+未知占用、任务累计、并发预留、最大输入/输出、无自动提额 |
| 检索或认知 | 跨项目隔离、未来章节排除、待复核排除、秘密与信念反例 |
| 备份恢复 | 一致快照、坏包/路径/hash、源项目保留、撤销、迁移、Windows 文件句柄 |
| UI | 真实浏览器操作、刷新重开、未保存保护、旧响应不抢编辑、新章不回跳 |
| Skill | schema、样例/反例、版本固定；专业效果以明确模型评测或人工阅读验证 |
| 数据迁移 | 旧库升级、引用与 hash 保留、失败回退、较新 schema 拒绝写入 |
| 媒体/游戏 | 真实工程打开/编辑/运行、规则与存档一致、局部修改传播；不能手填 PASS |

以下为里程碑检查示例，不是每次小改动必须全跑的清单。backend/web已存在；前端当前package scripts只有build与test:browser，其他检查显式调用已安装工具，不编造不存在的脚本。依据风险选择检查并核对每个退出码：

```powershell
Push-Location backend
go test ./...
go vet ./...
gofmt -l .
Pop-Location
Push-Location web
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit
node node_modules/eslint/bin/eslint.js .
# 格式检查按本次修改文件显式传入，存在相应配置时执行。
pnpm run build
pnpm run test:browser
Pop-Location
```

gofmt 列出文件即格式门禁失败，不能只检查退出码。MySQL 集成测试使用独立真实测试库，缺数据库时不得静默跳过后宣称全部通过；不能用 SQLite 模拟行锁或 FULLTEXT。竞态检测在具备对应工具链的环境执行，未满足 Windows race 工具链条件时明确记录，不编造通过。使用锁定的本地工具路径；脚本与配置以仓库现状为准，未配置的门禁明确记缺口。

以上是顺序执行的命令示例；每一步检查退出码，前一步失败不能因后一步成功而宣称全部通过。历史Python/React测试仅用于迁移对照，不作为正式新栈检查入口。任何会清理的测试临时目录必须是专用目录，绝不能指向`data/`、项目根或未知路径。并行检查使用不同临时子目录和端口。

浏览器测试使用隔离数据和测试 Provider，生产启动器不能通过普通请求参数切换到测试模式。真实付费模型验收单独标记授权额度、实际输入、用量与质量结果。

## 15 贡献流程与版本控制

- 开始前检查工作目录、分支和未提交修改；保留已有工作，不使用强制重置或清理整个目录。
- 使用独立功能分支；提交代码、部署、创建收费资源和发布作品分别遵守相应权限与审批策略。
- 根据风险执行相关测试；测试通过后没有新变化/风险就进入交付，不反复跑相同测试制造等待。
- 重要行为修改需要独立审查或明确标注未独立审查。核对建议与需求契约，修复实质问题，不机械扩大范围。
- 提交信息写明具体行为，例如 `fix: prevent stale chapter confirmation`。不要把日志、真实小说、密钥、运行数据库或虚拟环境提交到代码仓库。
- 重大决策在 `docs/` 中记录背景、选项、选择、代价和何时重评。先保护数据和费用，再考虑扩展性能。
- 维护依据是仓库代码、需求、决策和实施状态；不得把未记录的会话内容作为隐含技术要求。

新增小说入口与人物规则：五步必填向导支持草稿恢复和幂等创建；角色复用稳定 IP ID，改名不换身份，重要变更产生影响报告、重新校验与新版本。相关验收不得用空页面代替。

## 16 完成定义

一次功能交付完成，必须同时满足：

1. 作者可实际操作该功能，或对应后台能力被真实业务路径调用；没有假按钮和固定输出冒充模型。
2. 正常与关键失败路径可解释，持久状态一致；费用和权限约束在服务端执行。
3. 与改动相关的测试、类型检查和构建实际运行，并报告结果；未执行的验证明确保留为待验。
4. 变更不破坏旧项目和已确认正文；需要迁移时已有备份与升级验证。
5. 架构、接口、操作说明与实现一致，已知限制被记录。
6. 交付记录说明变更、验证和缺口；不能把测试夹具、文档审查或构建通过升级成真实模型质量或生产规模证明。

## 角色批量与局部修订契约

## v1.7 记忆、版本与验证纪律

1. memory item、revision、evidence、checkpoint、manifest使用类型化契约；必须保存权威类别、有效时间、权限/视角和来源，缺关键字段不得默认为公共正史。服务端强制跨项目/分支过滤，不能依赖prompt。
2. 核心主题/人物/高光锚点与因果依赖不能进入普通top-k淘汰；预算不足结构化返回缺口。token数采用相应模型tokenizer或标明保守估算，不把中文字符数写成精确token数。
3. cache key包含租户/分支/权限epoch/视角/时间/内容修订/编译器等全部作用域；读缓存仍验证权限和撤销。容量、TTL、并发合并有上限；cache丢失只影响性能。草稿、费用、任务进度写MySQL。
4. 摘要和模型提炼有来源coverage并保持候选状态，不能以摘要替代原件或修改权威事实。源改动同时触发派生失效与依赖传播；必要状态未就绪只阻塞受影响任务，不盲目重跑全书。
5. 新记忆表迁移须同步snapshot/log/retention/删除撤销与恢复登记；schema、来源或权限变化触发定向反例和一次集中恢复验收。不能先落表再补保护登记。
6. 工具链分发固定版本、来源和hash/已验证签名类型；新解释器建独立环境。二进制依赖检查尊重abi3和Requires-Python，不强装不同ABI、不隐式源码编译、不以轻量子集通过冒充AI/OCR迁移。生产数据库只在副本升级与恢复合格后安排切换。
7. 日常改动按风险验证；一次缺陷保留一个有效反例即可，现有证据仍适用就复用。安全/费用/并发/恢复关键边界不可跳过；数据库、浏览器、长篇压力和质量在节点集中检查，不每个字段都反复全仓回归。
8. 报告分开列设计、已实现、单元/集成/浏览器、真实模型、人工质量、部署状态。组件通过不等于端到端；文档改动只做文档链接/范围检查。未执行的模型或人工评测记NOT_RUN，并保留具体缺口。
9. 维护入口见[实施状态](IMPLEMENTATION_STATUS.md)。作者采用和规划确认按版本门禁执行，工程自动化不能替代创作确认、费用启用或专业资格。

## 支持环境

当前安装与验证目标为原生Windows、本机loopback。非Windows凭据保护返回`ErrVault`，工具进程隔离要求Windows Job Object；安装锁也限定Windows。保持Host、Origin、令牌和同源保护；Linux、Docker及公网部署需补齐凭据、隔离和访问控制实现后独立验收，不能仅以Go可跨平台编译推断可部署。

详细领域设计见[统一记忆架构](UNIFIED_MEMORY_ARCHITECTURE.md)，本规范和[最终方案v1.7](FINAL_PLAN.md)共同约束R131—R146。
