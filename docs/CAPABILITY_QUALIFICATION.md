## 可信评测与证据

`backend/internal/qualification`包含共享JSON契约/越权拒绝、来源账本的事实/错误信念/传闻/重复引文/秘密知情/作者计划检查，以及上述小说语义套件。评测集、版本、哈希、评分代码和策略与作者编写的Skill/Agent/Tool分离。HTTP只接受已编译的suite ID，不接受答案、门槛、分数、`passed`或审核策略。公开任务描述和输入可查看，保留答案不进入模型提示词或可编辑HTTP字段。

共享机械套件的每个任务在无方法、现有基线、候选版本三个分支中分别执行两次；小说语义套件按前述每组200份、每份一次执行。模型分支通过实际`Generations`原生协议、加密凭据库、费用预留、一次派发和使用量回执；工具分支通过实际`ToolTrials`固定镜像和一次性隔离客体。预置对照包含完整方法包和可执行工具，不靠预写成功文本充数。不同分支固定相同输入与模型配置，使用独立上下文。缺基线、不支持的工具依赖、缺运行环境或未知供应商回执明确为BLOCKED/NOT_RUN，不当作通过。

逐步骤记录子任务ID、原始输出对象哈希、输出、独立检查、使用量、费用、时长和人工修复次数。当前自动评测不修改产物，人工修复次数为0。共享机械套件要求所有候选任务和负例通过，小说语义套件使用前述90%门槛；基线和无方法的实际失败同时保留，不能从统计中删除。最终报告不可变保存为内容寻址对象，并进入固定备份引用图。

报价逐臂、逐任务构建最终请求，包含完整候选与基线方法包文本、输入、系统指令和输出契约；冻结请求哈希、字节数及单次预留。实际准备和派发不能把较大的基线或方法文件排除在估算外。当前可信策略为 `repository-deterministic-v3`，旧策略报告须重评，不能继续启用。

不符合模型输出契约的结果仍保存为失败诊断对象并保留实际使用量；普通生成接口不会将该诊断当作可采用的合格输出。未知回执单独记录为 UNKNOWN，未取得的使用量和时长标为未知，不用 0 冒充已确认的测量值。

## 资格范围与维护批准

资格固定能力版本及其完整 manifest 哈希、任务种类、suite 版本/哈希、模型连接和修订/公开参数，或工具运行镜像/包依赖哈希、实际执行证据。模型当前参数只包含精确 `max_output_tokens` 档位；改变该值需要重新评测。不是“小于等于已测上限即可沿用”。角色绑定、模型修订或凭据轮换都会在派发和结果使用时重新检查。

三臂使用同一冻结模型和精确输出档位，或同一固定工具镜像。已有当前用途绑定时，本次配置必须与其冻结配置一致；不把“用新配置重跑旧方法”冒充旧绑定原配置表现。需要轮换配置时，owner 明确停用当前绑定并清除用途头（历史保留，使用该固定绑定的任务停止），然后明确选择初始基线和新配置，完整重跑三臂评测后启用。未实现双配置混合计费对照，因此不兼容的比较明确为 BLOCKED/NOT_RUN。该重建流程不释放或重发此前已经派发且回执未知的请求。

内置独立确定性评分器只能授予`mechanical.contract`或`mechanical.source-ledger`的精确用途资格，有效期30天。**它不授予文学质量、专业语义泛化、视觉质量或游戏试玩质量资格。** 专业能力仍须相应独立评审与实际作品证据，本地协议替身的成功不能当作真实模型质量。

新增可执行工具依赖在机械检查通过后保持`REVIEW_REQUIRED`。维护角色须根据固定manifest、suite、镜像和实际隔离报告单独批准。普通Author/editor无法修改可信答案、评分器、审核策略或授予资格。单人工作室的owner可以承担维护职责；维护权限、AgentAuthor模型角色和自动评分器权限分别实现。

## 运行、启用和回退

开始评测使用 actor operation ID 幂等记录和事务 outbox；Temporal 推进独立子任务并跨重启恢复。未知供应商回执保留费用占用且禁止自动重发。完成记账和失败终结使用耐久重试，数据库长时间不可用不会通过重新请求供应商来“恢复”。暂停后已准备但尚未派发的子任务也停在派发门口；取消释放未派发费用，未知或已经发出的费用仍按真实回执对账。

owner 只能将仍有效的精确资格通过 expected-binding CAS 写入用途头。每次启用保留不可变绑定记录；回退也创建新绑定头，目标必须是历史上实际启用且当前仍有效的资格。已过期、已停用、配置不匹配或祖先已撤销的资格不可回退。

切换头只影响后续选择；运行中 Generation/ToolTrial 保留绑定 ID 和资格 ID，在派发、输出读取和采用检查点验证当前权限、来源祖先、scope、suite 和精确配置。单独停用绑定会在下一检查点阻止使用它的任务。

新建任务在初始准备和最终入库事务都必须使用当前用途头；显式传入仍启用的历史绑定也不能绕过。相同 operation 的重放返回原任务，已经准备的任务继续固定原绑定。

“撤销资格”界面明确标为**撤销整个能力版本及依赖用途**：实际写入现有受保护 capability 撤销账本，整个版本、派生版本和依赖它的资格都会失效。回退与单独停用不声称写入这个广泛撤销记录。

## 周调度、页面与恢复

每个项目明确opt in才开启产品内每周评测，每周费用上限默认0。全局预算、项目每周授权、当前操作者权限、基线或分支条件不满足时，在派发前停止并保存具体待处理原因。本地工程验证使用隔离测试传输，不要求真实供应商凭据。

schema 29 为每个项目和 UTC ISO 周保存唯一费用账本，并把每次评测调用关联到冻结的调度版本和步骤。预留、实际费用、取消和对账在同一事务更新全局与周账本。修改或停用计划使旧版本停止发送；同周重新保存不会清除实际费用或 UNKNOWN 占用。未知请求继续占用，只有未发送请求可释放；意外超过预留的真实账单仍记入债务并阻止后续发送。

父评测进入取消、阻塞或失败后，独立的 receipt-only outbox/Temporal 流程仍收集终态、实际费用、已接受回执的诊断原物和对账版本。它不请求供应商、不重新评分或授予资格。当前步骤费用可随晚到账单更新，已保存报告的字节和哈希保持不变；费用已知与使用量已知分别显示，人工账单不能冒充已取得执行用量。

子任务与步骤的绑定和队列/费用预留在同一事务提交；关联失败会整体回滚。历史关联缺口仅按可信调用映射或精确的内部操作记录恢复。终态清理仅停止未终结子任务，已完成/失败/拒绝的真实结果不因父任务失败而改写；独立暂停的未发送子任务仍会释放占用。

Skill 页面提供 suite/固定版本选择、费用估算、实际运行进度、三组比较、检查和报告、执行依赖批准、精确用途启用、历史回退、停用及广泛撤销。轮询只更新选中任务状态，不覆盖未提交表单；销毁组件或改变项目后忽略迟到响应。

周计划保留独立的已保存范围，重新进入页面可直接停用。只有明确“使用上方范围”才替换周计划范围；开关、金额和范围变化都参与未保存修改保护与放弃操作。

schema28、29 的已应用历史 checksum 保持不变。schema30 为调用映射增加原生/历史来源和证明，DDL已生效但回填失败时仍可重跑；原生29/30的调用映射缺失不会自动当作旧记录修补。固定备份图显式兼容旧24至29；当前归档双向核对步骤、Generation、model call、冻结周归属、币种、占用与实际费用，拒绝删除映射、改挂到另一周、清空grant、清零UNKNOWN占用或整数溢出。
