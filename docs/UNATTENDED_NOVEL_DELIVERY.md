# 维护与验证指南

当前实现状态统一见[实现状态](IMPLEMENTATION_STATUS.md)，产品范围见[需求追踪](REQUIREMENTS_TRACE.md)，安装与支持平台见[本地安装](LOCAL_INSTALL.md)。本文件保留维护入口，文件名仅为既有链接兼容，不定义无人值守任务或个人执行指令。

## 维护步骤

1. 确认仓库位置、版本锁、运行实例、工作树改动和数据备份。复用已完成的检查，不覆盖无关成果。
2. 从需求ID定位未完成的业务结果；产品设计和历史工程方案不作为已经实现或通过验证的证据。
3. 使用明确范围的单元、脚本或隔离集成检查；不因文档修改运行安装、迁移、真实模型或完整恢复演练。
4. 实际模型请求必须具备Key、有效价格和明确开启的预算。普通内置试写无需完整评测套件；正式审稿发布与精确能力绑定仍执行对应资格门。
5. 模型、工具、账号和权限的变更保留版本与来源。未知费用或结果先对账，不自动重发；依赖或资料变化使旧候选失效。
6. 发布实现状态时记录代码、适用环境、检查范围和剩余条件；不记录私人账号、完整机器路径、会话、Key或作者正文。

## 运行保护

- 使用现有持久数据目录，禁止重新初始化已有工作室或把测试库变为正式库。
- 保留MySQL权威数据、不可变对象、受保护撤销账本、模型凭据和备份之间的边界。
- 恢复仅建立独立副本；恢复出的用户、任务、费用和能力资格按恢复契约重新核对。
- 外部脚本、网络访问和收费资源不从安装或维护动作获得默认许可。
- 服务端继续保留回环、Host/Origin及当前权限保护。服务器部署需要独立适配与验证。
