# 长稿分章导入与续导

在小说工作台选择“长稿分章导入 / 续导”，将已有原稿转换为可手动编辑的章节私稿。此过程为本地确定性处理，不调用模型，不自动生成世界观、剧情事实或正史记忆。

## 操作流程

1. 上传原稿，或选择已上传的资料。原文件按原始字节保留，可随时下载；解析失败也保留原文件，并提供重新解析入口。
2. 选择“分章预览 / 继续该原稿”。识别中文章节、英文 Chapter 和带 Markdown 前缀的章节标题；未分章文本作为一个待调整段。章节标题、空行及换行保留在正文中。
3. 逐段查看原文与重复核对。可改标题和卷名、调整顺序、在光标或指定原文位置拆分、合并原文相邻段，或明确跳过。每个位置使用 Unicode 码点，分章必须完整覆盖已解析文本，不能遗漏或重叠。
4. 保存分章方案后导入本段，或从未完成处连续导入。每章保存独立进度；出现需要处理的问题即停止。可选择“本章后停止”，重新打开记录后续导。
5. 通过“打开已导入章节”进入现有编辑器，使用自动暂存、正文对照、修订历史和旧稿取回；保存后返回原导入记录。需要进入原有规划流程时，复制记录中的章节编号，在分卷规划里选择“将已有章稿加入本卷草稿”；系统先只读核对该章，再引用相同编号，不重新创建或改写正文。

相同原文件及相同解析文本复用已有导入记录，不重新创建章节。同名只提示核对；完全相同正文默认阻止另存，作者可明确选择另存、跳过，或选择现存章稿进行替换。替换需要确认，并在同一事务核对目标版本、保存替换前正文及导入结果。目标已变化时保留当前稿，重新核对后再操作。

## 容量与解析边界

- 原文件最多 32 MiB；专用长稿规格支持最多 8 MiB 的已解析文本，最多 2,000 个分章段。普通资料入口原有 256 KiB 规格不变。
- 解析报告按编码后最多14MiB单独校验，不放宽普通记忆文档限制；特殊字符转义或元数据导致报告超限时保留原文件，标为解析待处理，不截断文本冒充成功。
- UTF-8 TXT/Markdown 优先。原始 BOM、CRLF 和全部字节保留在下载文件中；解析文本去掉开头 BOM，其他字符不改写。
- DOCX复用既有安全解析器：单个 Word XML 部件最多 4 MiB，归档解压总量最多 64 MiB，段落及其他结构上限保持不变；图像、修订等未处理部分明确列为遗漏。长稿规格不会绕过这些限制。
- PDF和图片复用普通资料/OCR规格，其页面、文本及本地组件限制不变。部分解析必须先核对并明确接受，不能把已识别部分当作全文。
- 原文预览每次最多 20,000 码点；单章继续受现有 100,000 码点及 256 KiB 保存体积限制。超限段保留为可调整、可重试状态，先拆分再导入，不静默截断。
- 重复核对使用当前作者已保存私稿，没有私稿时核验已采用正文。每段最多返回 20 个匹配；单次至多核对 200 个候选来源，存在更多或不可读来源时明确标为未完整核对。相似情节和改写文本不等于精确重复检测。

## 保存与恢复契约

原稿使用既有 `source_imports`、不可变对象及作者 `import_drafts` 保留根。分章布局为私人 `novel_manuscript_import` 资源，小型逐章进度为 `novel_manuscript_progress` 资源；均复用已有数据库、来源登记、日志及备份，不增加表或迁移。

每次明确请求只推进一章。正文、替换前留版和本章结果在同一事务中提交，失败一起回滚；已完成段不能重新切分或再次执行。布局和目标正文分别校验修订及摘要，操作编号核对重复回执。页面只在前台请求后续章节，离开后不会后台继续；服务重启后读取数据库中的结果续导，不重新上传或改写已完成章节。

读取有 15 秒时限。写入只限制界面等待，不取消原请求或自动重发。响应未知时保留操作编号，提供只读核对与明确的同一请求重试；权限拒绝清除服务端内容视图，迟到成功不能恢复已撤回内容。

导入稿标为 `unplanned`，可在规划完成前手动编辑；AI续写、独立记账及发布继续要求现有规划门。在规划中使用该稿的稳定章节编号建立细纲并明确更新依据后，方可进入原有生产流程；导入本身不创建或采用大纲。卷名和顺序当前属于导入方案元数据，不自动替换已有全书规划。

布局及进度不能通过通用资源编辑器改写、发布、自动索引或显式进入模型上下文。实际章节私稿继续遵循原有工作资料策略。完整备份保留原始文件、布局、正文和进度；恢复账号及权限仍需既有授权。独立项目恢复副本重映射来源和资源编号，保留记录供核对但不直接续导，避免把旧执行结果当作新项目写入资格；需要继续导入时重新选择原稿建立新记录。

工程验证采用隔离数据库和本地 HTTP 浏览器流程；它不代表真实模型、长篇文学质量或独立介质灾难恢复资格。
